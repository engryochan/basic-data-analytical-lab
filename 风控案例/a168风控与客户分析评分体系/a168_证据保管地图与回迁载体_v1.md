## 三、新增等级 `TRANSCRIBED-STDOUT` 及其硬上限

**定义**：逐字稿原样保存之机器读数，且该读数当时作用于第一手上载档。

**为何强于「模型结论」**：读数由工具产出，非模型措辞；逐字稿保留原文。
**为何不得升 🟢**——本项目已实测之验证器失效率：

```
自纠册现行 31 条中，验证器缺陷 10 条
SC-002 / 007 / 016 / 017 / 018 / 020 / 026 / 027 / 029 / 030
失效先验 ≈ 32%   →  约三分之一的「已核过」，核的是坏尺
```

**升格唯一路径**：本机重跑同一读数并对账。**不得由「当年跑过」直接升格。**

## 七、铁律定稿（承 Ryo 裁示，收窄措辞）

> **一、降级不禁，无证降级禁。**
> 降级与升级举证责任对称：二者皆须正向证据。
> 合法降级唯二途：**原判据被证伪**，或**被证越出适用域**；须入 SC 册，载明原判轮次与撤回理由。
> 「我没看到」「保守起见」**不是证据**。
>
> **二、证据不足不是降级理由，是彻查理由。**
>
> **三、「彻查」之定义 = 走完冻结取证序，非「必须交出 STOP CAUSE」。**
> 终点有二：寻获 Trace，或 `E05→E01→E02→E04→L01~L10→E03` 全序走完仍无 Trace
> → `UNRECOVERABLE · NO_TRACE`，**此为合法结清**（第五条红线）。
> 若「水落石出」被读成「必须得出机制」，反会逼出越级。
>
> **四、证据在另一模型处 ≠ 本模型之 PROVEN；亦 ≠ 没有证据。**
> 但须加一句：**证据在另一模型处，多数情形下等于「在您本机」——模型只留逐字稿。**

```
查不到 ≠ 没有        没上传 ≠ 没发生
没看到 ≠ NO_TRACE    未核验 ≠ 证伪
模型有过 ≠ 模型现有   逐字稿有 ≠ 原件在
```
