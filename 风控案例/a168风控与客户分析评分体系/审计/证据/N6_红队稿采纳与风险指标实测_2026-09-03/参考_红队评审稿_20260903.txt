# 三、Killcritic：`intersect()` 静默吞掉判据，是必须封杀的

我认为这是本轮最危险的发现。

如果引擎是：

```r
intersect(requested_columns, actual_columns)
```

然后继续运行，那么：

```text
criterion A
requested = c("silent_days", "roi", "n_rounds")

actual = c("roi", "n_rounds")

intersect()
      ↓
c("roi", "n_rounds")
```

程序：

> **不报错。**

但业务上实际发生的是：

> **`silent_days` 这一判据被无声删除。**

这比 SQL syntax error 更危险。

因为：

```text
SQL error
→ 人会发现

silent omission
→ 人可能永远不知道
```

因此我建议正式加入：

## **KILL RULE：Criterion Silent-Drop Prohibition**

凡是：

```text
registered criterion column
        ∉
actual source columns
```

不得：

```r
intersect()
```

后静默继续。

至少必须产生：

```text
criterion_status = BLOCKED
criterion_gate_reason = COLUMN_NOT_IN_DECLARED_SOURCE
```

而不是：

```text
criterion_status = OK
```

更不能：

```text
criterion = omitted
```

无声消失。

# 四、四级阶梯现在还要再加一层“语义来源”

先生前面要求的：

```text
SOURCE_EXISTS
→ SOURCE_ALIGNED
→ SOURCE_ADMISSIBLE
→ CRITERION_ELIGIBLE
```

现在仍然成立。

但本轮已经证明，仅靠这四层还不够。

因为：

```text

```

可以发生在：

> 总包内部 CTE 确实计算过 `silent_days`。

但是：

```text

```

因为它根本没有成为该交付表的输出字段。

所以建议最终形成：

```text
SOURCE_EXISTS
      ↓
OUTPUT_EXPOSED
      ↓
SOURCE_ALIGNED
      ↓
SOURCE_ADMISSIBLE
      ↓
CRITERION_ELIGIBLE
```

### 新增的关键门：

**`OUTPUT_EXPOSED`**

意思是：

> 这个字段不是“总包曾经算过”，而是**真正存在于声明的交付件输出中**。

这正好封住本轮 8 个 CTE alias 漏洞。

# 五、Blindspot：`audit_rn` 是强证据，但不要把它绝对化

先生目前用了：

> “不在 `audit_rn` 排序键 → 不是输出列。”

这个方法对于本包非常有价值，但我建议工程规范不要写成：

```text
audit_rn ∉ column
→ definitely not output
```

而写成：

```text
audit_rn
    ↓
strong output-column evidence
```

最终还是必须以：

```text
actual CSV header
```

或实际表 schema 为最终证据。

否则以后某个模块改变排序键定义，Atlas 自己又可能制造新的假阴性。

所以优先级建议：

```text
真实交付件 header / schema       LEVEL 1
实际 CREATE TABLE / SELECT 输出  LEVEL 2
audit_rn 输出排序引用             LEVEL 3
CTE alias                         LEVEL 4
注释/命名推断                     禁止作为最终证据
```
