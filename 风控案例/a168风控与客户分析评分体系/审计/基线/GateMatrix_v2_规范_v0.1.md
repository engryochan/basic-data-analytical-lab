## 〇 · 立此规范之由（四次假判之共同根因）

| # | 假判 | 形态 | 方向 |
|---|---|---|---|
| SC-02 | `bet38` 判据漏 `UPPER(TRIM(r.bet38))` 之双右括号 | 假 FAIL | 判缺而实有 |
| SC-06 | 段边界取「受检条目锚」致吞并后续语句 | 假 PASS | 判有而实无 |

**共同根因**：以**文本模式**回答**语义问题**。且已证明一件事——
**「正则覆盖率 100%」是不可证命题**：`⟨col⟩ AS STRING) =`（跨行 CAST）之存在说明，任何模式都可能被下一种合法写法绕过。

> 故 v2 之目标须改写：
> ❌ 不再追求「自动证明 63 条 SQL 全部符合闸门」
> ✅ 改为「自动证明**声明与代码是否一致**；不能证明者，明确进入人工复核」

## 一 · 三层事实模型

| 层 | 谁产生 | 可否直接裁定 |
|---|---|---|
| `FACT-C` 候选事实 | 机器（AST／parser） | ❌ |
| `FACT-A` 人工声明 | 人（条目内 `▸ 闸门` 声明／既有登记册） | ❌（单独亦不可） |
| `CONSISTENCY` 一致性 | 机器比较二者 | ✅ 可产生**事实层**状态 |
| `WAIVER` 豁免 | 人 | ✅ |
| `FINAL GATE` 治理裁定 | 规则 ＋ 人 | ✅ |

**⛔ 明确否决 `Declaration-only`**：若机器不验代码，声明即成自证——「声明有 `bet02='101'`、代码实无」将无人察觉。故为 **Declaration-first ＋ consistency check**，非 Declaration-only。

---

## 二 · 两段式状态机（事实层与治理层不得跨越）

### 2.1 事实层（机器产出，三态）

```
CONSISTENT              声明与代码一致
DECLARATION_MISMATCH    声明与代码不符（⛔ 二者皆不得默认为准）
PARSE_UNKNOWN           无法解析／无法归一／存在歧义
```

### 2.2 治理层（须先有事实层状态方可进入）

```
CONSISTENT
    ↓
是否存在缺闸？
    ├─ 否 → PASS
    └─ 是 → 是否有点名该 Gate 之明确豁免？
              ├─ 是 → WAIVER_DECLARED
              └─ 否 → FAIL

DECLARATION_MISMATCH → 人工复核（禁自动裁定）
PARSE_UNKNOWN        → 人工复核（禁自动裁定）
```

> **危险跳跃之禁令**：「AST 没找到 `bet02` → FAIL」——**禁止**。
> 未找到只能进 `PARSE_UNKNOWN` 或据声明比对，不得径判缺闸。

## 三 · 八条铁律（SC-23-A～H，正式入册）

| 编号 | 内容 |
|---|---|
| **SC-23-A** | 不得以 regex existence 直接裁定 PASS／FAIL |
| **SC-23-B** | AST／parser 仅产生候选事实，不直接产生治理裁定 |
| **SC-23-C** | 所有声明必须能回指 v10 原文**锚行** |
| **SC-23-D** | 代码无法解析 **≠** 缺闸 |
| **SC-23-E** | 声明与代码不一致 → `DECLARATION_MISMATCH` |
| **SC-23-F** | 存在无法归一之表达式 → `PARSE_UNKNOWN` |
| **SC-23-G** | PASS／WAIVER／FAIL 须在事实层之后，由治理规则产生 |
| **SC-23-H** | validator **自身不得修改、补全、猜测** v10 声明 |

> SC-23-H 之要害：否则 validator 会沦为「偷偷替数据作决定的第二套 SQL」。

## 四 · Rule C 改造：由「计数」改为「声明 ＋ 血统证明」

**旧法（作废）**：`bet05>0` 命中 37／63 —— 数字漂亮而危险，口径混杂（原始列守门／派生别名守门／无关文本三者混计）。

**新法**：声明写原始列，机器解表达式血统。

```
声明：▸ 数值守门 bet05 > 0

机器须解：
  SOURCE_COLUMN = bet05
  DERIVED_ALIAS = b13        ← CAST(NULLIF(TRIM(bet05),'') AS BIGINT) AS b13
  PREDICATE     = b13 > 0
  LINEAGE       = RESOLVED
→ CONSISTENT
```

若见 `b13 > 0` 而**追不到** `b13 ← bet05` 之可靠来源：

```
→ PARSE_UNKNOWN（⛔ 不是 FAIL）
```

**⛔ v2 不再产出 `bet05>0 = 37` 一类总计数**——该数无统一口径，属「漂亮而危险」。

## 五 · 声明格式（`FACT-A` 之载体）

承既有「▸ 导出：需要／不需要」单一体例，增设第二、三条声明行：

```
-- ▸ 闸门：Identity[bet02,rn] · Population[age022,category] · State[bet38]
--          · Quality[bet05>0,bet08 非空,bet11>0,bet04>0]
-- ▸ 豁免：age022／category／bet38 —— 本条检验字段语义，语义不因测试线或重对单而异；
--          加闸缩样反失分叉证据，改以分层输出替代（见输出列 by_bet38）。
```

**格式约束**：
1. 豁免理由须**点名具体 Gate**；泛化理由（「本 SQL 为特殊用途」）**不构成有效豁免**——否则 WAIVER 沦为后门。
2. 声明须可回指锚行（SC-23-C）。
3. 声明由人写；机器只读、只比、不补（SC-23-H）。
