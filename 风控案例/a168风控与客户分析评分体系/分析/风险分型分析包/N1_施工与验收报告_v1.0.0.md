## 三、N-1B · `R24b` 负向保证有效性闸（状态：`PATCHED`）

### 3.1 病灶复述（本轮机器实证）

`P-16`（禁以实现输赢符号定罚，S1，由 G-07／PI02／X_combo 三条独立实证支撑）
其 `negative_assurance_evidence` 全文为：

> `criterion_family 栏机检：OUTCOME_BASED 者 admit_to_risk_decision 恒 FALSE`

而全册 `criterion_family` = **51 STRUCTURAL + 15 REFERENCE_ONLY + 0 OUTCOME_BASED**。
**被检集合为空 ⇒ 恒真而无内容。** 且 `T-07 / win_rate_all`（胜率，纯结局量）
现标 `STRUCTURAL`——正是把本该受检者移出了被检集合。

`verify_registry_dual.R` 头部本已立「`coverage_observed` 必填，防零对象空跑得 PASS」之铁律，
但 `R24` 只检 `negative_assurance_evidence` 之**存在性**（`na_missing`），
不检**有效性**。故 P-16 之空检会顺利通过 R24。

### 3.2 实作

新增 `.r24b_core(Y, D)` 与 `test_r24b()`，判 rule_id `R24b`：

| 态 | 触发条件 |
|---|---|
| `PASS` | 凡有绑定者 coverage 皆 > 0 |
| `FAIL` | 至少一条绑定 coverage == 0（`VACUOUS_ASSURANCE`）|
| `NOT_RUN` | 有禁令声明「机检」却无绑定，或绑定所指之栏不存在 |

### 3.3 「不被吞没」之证明（参考稿 §三之硬要求）

`report_verify()` 之总判为 `gate <- if (FAIL == 0 && NOT_RUN == 0) "PASS" else "NOT_PASS"`。
`R24b` 系 `chk()` 之正规一行，故其 `FAIL` 或 `NOT_RUN` **必然**令 gate 转 `NOT_PASS`，
无从被降为「辅助信息」。**此非承诺，系聚合式之数学后果。**

### 3.4 对真实双档之预演实判

```
禁令总数 = 20 ｜ 声明「机检」者 = P-15, P-16, P-17, P-18, P-20
  P-15 [window_scope     = FULL_WINDOW  ]  coverage =  66   ✓
  P-16 [criterion_family = OUTCOME_BASED]  coverage =   0   ✗ VACUOUS
  P-18 [ranking          = FALSE        ]  coverage =   4   ✓
  未绑定 = P-17, P-20
★ R24b status = NOT_RUN
```

**两条独立理由并存**：① P-16 已坐实 VACUOUS；② P-17／P-20 声明机检却未绑定。
二者皆令第二阶段闸 `NOT_PASS`——**这正是本闸应有的表现，非缺陷。**

### 3.5 只增不减之机器证明

`before` 全文逐行比对 `after`：**仅 3 行**未原样存续，皆为已具名之必要改动——
① 版本头注（1.0.0→1.0.1）；② `verify_v1_5_001` 签名 `(Y)` → `(Y, D)`；③ 其呼叫点。
