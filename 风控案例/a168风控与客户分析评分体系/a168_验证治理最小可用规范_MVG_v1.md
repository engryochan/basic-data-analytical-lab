## §一、回归停机定理（本规范之地基）

验证链的终止方式，逻辑上只有三种：

```
① 无限回归   L8、L9、L10…       → 永不落地
② 循环       L7 ↺ L0            → 自证闭环
③ 公理停机   终止于系统之外的锚  → 唯一可行
```

**加 `Meta-` 前缀不改变拓扑。** 换名字不等于换结构。

### 三锚（本项目仅此三者可作停机点）

| 锚 | 为何不需被本系统验证 | 本项目已有实例 |
|---|---|---|
| **A1 数学恒等式** | 不经任何工具；算术不因工具失效而变 | `字节差 = 行数`；`4096 + n×65536`；`181×100,000＋39,550` |
| **A2 机械可复算** | 第三方跑同一脚本得同一结论,不需信任执行者 | 「星级须由闸门派生」（已锁） |
| **A3 预注册** | 判据在看到数据之前写死，时间序上不可被结果污染 | §十 `E03`「n=3 固定、禁 optional stopping」（已锁） |

### 定式

```
L1  业务验证器  ──验──▶  被检对象
L2  独立交叉器  ──验──▶  L1
        ↓
  落于 A1 / A2 / A3 之一   ← 停机，不设 L3
```

**停机判据**：**「是否已落在锚上」**，非「是否验得够严」。
落上了，一层足；落不上，十层仍循环。

### 派生禁令

- **禁**：以「再加一层 Meta-」作为回归之解。
- **禁**：验证链之末端指回链内任一节点（含 `↺ 回到 L0`）。
- **须**：每条验证链在册中明写其停机锚编号（`A1` / `A2` / `A3`）。**无锚者等级封顶 🟠。**

## §三、四维正交评级（取代八维＋二元）

### 收敛理由

十维彼此高度相关——**在验证器身上讲了三轮的共模，套到评级维度上一样成立**。
十个相关维度不比四个正交维度多出信息，只多出填表工。

| 正交维 | 核心问题 | 吸收原维度 |
|---|---|---|
| **AUTH 真实性** | 这是不是那个东西 | Authenticity + Traceability |
| **CORR 正确性** | 算得对不对 | Accuracy + Consistency + Completeness |
| **SCOPE 适用域** | 它**不能**回答什么 | Feasibility + Evolvability |
| **INDEP 独立性** | 谁来担保 | Independence + Reproducibility + Reliability |

### ⚠️ `INDEP` 须移出 min 池

**木桶取 `min` 已锁。若 `INDEP` 入池：** 单人项目无第三方复核 → `INDEP` 对**所有**结论恒为 🟠 → **全册无一条可达 🟢**。

**处置**：`INDEP` **不参与 min 运算**，单列为「担保来源」标注栏，取值 `A1`/`A2`/`A3`/`无锚`。

> **独立性是证据的属性，不是结论的分数。**

### 记法

```
AUTH 🟢 ｜ CORR 🟢 ｜ SCOPE 🟢 ｜ 综合 = min(AUTH, CORR, SCOPE) = 🟢
INDEP: A1（数学恒等式）          ← 标注，不入 min
```

## §四、Validator Passport（精简版·五栏必填）

> 完整版二十余栏延后。**当下五栏，缺一即封顶 🟠。**

```
VALIDATOR-ID        V-R03B-xxx-001
PURPOSE             本器回答什么（一句）
NOT-CAPABLE-OF      本器【不能】回答什么   ← 必填，防越级
NEG-CONTROL-RESULT  已知坏样本之【实际返回值】（非「应返回」）
SC-LINKED-DEFECTS   本器过往被 SC 记录之缺陷编号（无则填 NONE）
STOP-ANCHOR         A1 / A2 / A3 / 无锚
```

**三条设计要点**：

1. **`NOT-CAPABLE-OF` 必填** —— 例：`MD5` 能证字节同一，**不能证来源**。此栏防的正是「能力越域」，即自纠册中八条形状／数字越界之共同病根。
2. **`NEG-CONTROL-RESULT` 记实际值，非期望值** —— 写「应返回 FAIL」是自述；写「喂三行 CRLF 小档，实返 `cr=3`」才是证据。`SC-002` 若做此项，一秒现形。
3. **`SC-LINKED-DEFECTS` 强制回填** —— 与 §二 矩阵双向锁；无此栏则⑮永远不会被触发。

## §五、验证器生命周期 · 按复用次数分级

| 类别 | 阶段 | 说明 |
|---|---|---|
| **一次性**（跑完即弃） | 规格 → 正控制 → 负控制 | **三阶段。** 十五阶段在此为负收益 |
| **复用 ≥ 3 次** | ＋ 独立交叉 → 版本锁 | 五阶段 |
| **进生产／据以判级** | 全十五阶段 | 仅此类需完整 |

### 升级之反向条款（必加）

```
V12 Upgrade  ──▶  【回归测试】  ──▶  V13 Re-validation
                      ↑
        旧版本之正／负控制样本，新版本须给出【同样】结果
```

**否则「升级」会静默改变判据，而全册历史结论皆建于旧判据之上。**
**升级破坏可信度，比不升级更危险。**

## §六、本规范与已锁标准之对应（禁自创，禁机械叠加）

| 需求 | **用已锁标准** | 不用 |
|---|---|---|
| 数据质量维度 | **`ISO/IEC 25012`**（固有／系统依赖两类特性） | 自创八维 |
| AI 产出之验证器治理 | **`ISO/IEC 42001`** | 泛称「AI 风险管理」 |
| 数据集质量与生命周期 | **`ISO/IEC 5259`** | — |
| 风险登记与处置 | **`ISO 31000:2018`** | — |
| 严重度分级 | **本项目 S1–S4 三轴** | 另立 NCR 等级 |

**红队第八问常备**：我们是在引用标准，还是在自己写规则？
**自己写的规则须标 `T3 工程·本项目铁律`，不得冒充国际标准（T 轴纪律）。**

**`ISO/IEC 17025` 之核心机制（测量不确定度、计量溯源至 SI、实验室间比对）在此不适用**——MD5／行数／字节数为**离散确定性读数**，无不确定度，无 SI 可溯。**可借鉴者仅「方法确认」与「技术记录」两节，须明说边界。**

### ⚠️ 关于「验证器能力矩阵」之单体独立性栏

**独立性是 pairwise 属性，不是单体标量。**
`ρ(MD5, SHA-256)` **极低**（同一读取路径、同一档案句柄、同一 I/O 栈）；
`ρ(MD5, 字节差＝行数)` **高**（一个靠 I/O，一个靠算术）。
**给 `MD5` 一个「独立性：高」，恰好掩盖了这个差别。** 须改为对称 n×n 矩阵。
