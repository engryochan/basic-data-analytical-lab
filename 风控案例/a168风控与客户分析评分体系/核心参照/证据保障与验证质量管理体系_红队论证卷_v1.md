## §一、铁律定稿（收窄措辞，与 `SC-031` 相容）

「不允许降级」若作**绝对律**，则 `SC-031` 违律——该条正是把两项 🟢 降回未证，而那次降级**是对的**。绝对律会把自纠册最硬的一条判成违规。

律不在「禁降级」，而在**举证责任对称**：

| | 合法 | 违律 |
|---|---|---|
| 升级 | 新增正向证据 | 由形状／数同／推演升 |
| **降级** | **原判据被证伪** 或 **被证越出适用域**（入 SC 册，载明原判轮次＋撤回理由） | **「我没看到」「证据不足」「保守起见」** |

### 定稿四条

```
一、降级不禁，无证降级禁。
二、证据不足不是降级理由，是彻查理由。
三、「彻查」之定义 = 走完冻结取证序，非「必须交出 STOP CAUSE」。
     终点有二：寻获 Trace，或 E05→E01→E02→E04→L01~L10→E03 全序走完仍无 Trace
     → UNRECOVERABLE · NO_TRACE，此为合法结清（第五条红线）。
     若「水落石出」被读成「必须得出机制」，反会逼出越级。
四、证据在另一模型处 ≠ 本模型之 PROVEN；亦 ≠ 没有证据。
     且须加一句：多数情形下它等于「在您本机」——模型只留逐字稿。
```

### 两类降级之判别（防止 `SC-031` 被援为无证降级之先例）

| | `SC-031` | `A-05` / `A-06` |
|---|---|---|
| 形状 | 绿转非绿 | 绿转非绿 |
| 机制 | 原判据被同轮证据证伪 | 母证据在手而未看 |
| 判定 | **合法** | **违律** |

> **形合非机制**（口诀第六句）——此句用在纪律自身，与用在数据上同样成立。

## §二、自领两条

### `SC-040` · 以 observed defect fraction 冒充概率参数

**事实**：我曾写「本项目实测验证器失效率 `p = 10/31 = 32.26%`」，并据以输出至小数点后四位之共同漏检率表。

**缺陷有三层**（较 ChatGPT 所指更重）：

| 层 | 内容 |
|---|---|
| ① 分母错置 | 要估失效率，分母应为**跑过的验证器总数**（未知，可能数百）。`31` 是**已发现错误总数**，与验证器数量无关。**分子分母不同度量，比值无意义。** |
| ② 选择偏差，方向已知 | SC 册只登**已被发现者**；而验证器缺陷最难发现（发现它需要另一个验证器）。故 `10/31` 是有偏**下界**，非点估计。 |
| ③ 非独立且时变 | 三十一条非独立事件（同根因可生多条）；早期与晚期失效率不同（学习效应），混算平均无意义。 |

**性质**：形状／数字越界 · **S2**
**加重情节**：此错发生在**论证「验证器先验其自身」的那一段之内**。论证方法论严谨性的那个论证本身不严谨——不是巧合，是该原则的活体标本。

**处置**：数值撤回 ⚪；结论保留（见 §三）。

### `SC-041` · 循环论证：以由 N 导出之均值反推 N

**事实**：我曾写「由字节算术反推 DB62 实为 100,000 列：`38,424,595 ÷ 384.25`」。

**缺陷**：v3 §十 之 `384.25` 极可能本身即由 `38,424,595 ÷ 100,000` 算出。用它去「推出」100,000，是以结论证明结论。

**露馅点**：精确重算得 `38,424,595 ÷ 384.25 = 99,998.95`——**不是整数**。四舍五入过的均值反推不回原数。

**性质**：形状／数字越界 · **S2**

**正确分级**（一条须拆为两条）：

| 命题 | 等级 | 依据 |
|---|---|---|
| 档名 `43388` **不是**行数 | **🟢** | v3 §甲 原文「DB62[1:43,388]」为**比对区段**；且 885.60 B/行 ÷ 359.19 ≈ 2.466 倍，同 24 列 schema 不合理 |
| 行数 **= 100,000** | **🟠** | v2 原文 ＋ Query History `rows=100,000`；**本轮未实测** |

> **通则**：证据层不同者不得合并为一条 SC。「强，但应标明证据层」之正解是**拆条**，不是加标签。

## §三、撤回须精确：代数恒真部分予以保留

设两验证器各以 `p` 漏检、相关 `ρ`：

```
P(both fail) = p² + ρ·p(1−p)

相对单层之降幅 = 1 − q/p = (1−p)(1−ρ)      ← 闭式
```

**降幅 = (1−p)(1−ρ)，对 ρ 严格线性递减，ρ→1 时归零。**
**此式对任意 p ∈ (0,1) 恒成立，不需要知道 p。**

| 项 | 处置 | 停机锚 |
|---|---|---|
| 「共模时加层数无益，独立性是唯一杠杆」 | **保留 🟢** | **A1**（代数恒真） |
| `32.26%`、`ρ=0.9 时降 6.8%` 等数值 | **撤回 ⚪** | 无（`p` 无有效估计） |
| `SC-002 / 026 / 029` 为共模实例 | **保留 🟢** | 个案观察，非比例推断 |

> **不宜整块作废**——否则会把一条对的定性结论，跟着错的数字一起扔掉。

## §四、回归停机：三锚（**含 ChatGPT 之修正，已接纳**）

### 修正内容

我原写：「不需被本系统验证的锚」。**措辞过强。** 数学恒等式仍可追问其算术实现、字符编码、运行环境。

**修正后表述**：

> **三锚不是绝对不可验证的公理，而是当前验证链的终止条件。**
> 其正当性不在「不可置疑」，而在 **因果不相交**——
> **锚之失效路径与被检对象之生成路径无共同上游。**

这是 d-分离，不是公理化。**停机因此是相对的、可标注的、可在必要时再推一层的**，但不因此变成无限回归——因为「再推一层」须由**新的共同上游被指认**触发，而非由「更严谨」之愿望触发。

### 三锚定义

| 锚 | 与被检对象之因果关系 | 本项目实例 |
|---|---|---|
| **A1 数学恒等式** | 算术不经被检对象之生成路径 | `字节差 = 行数`；`4096 + n×65536`；`181×100,000＋39,550` |
| **A2 机械可复算** | 第三方跑同一脚本得同一结论,**不需信任执行者** | 「星级须由闸门派生」（已锁） |
| **A3 预注册** | 判据在时间序上先于数据，不可被结果污染 | §十 `E03`「n=3 固定、禁 optional stopping」（已锁） |

### 拓扑

```
L0  被检对象
     │
     ▼  业务验证器 L1
L1  验证结果
     │
     ▼  独立交叉验证器 L2
     │
     ▼
  A1 / A2 / A3 之一          ← STOP，不设 L3
     │
     ▼
  结论等级

  ✕ 禁：L2 → L3 → L4 → ∞
  ✕ 禁：L2 ↺ L0
  ✓ 许：发现缺陷 → 有限影响回溯 → 重新验证
```

### 对原七层图之指认（存证）

原 `L0→L7→↺L0` 图，其 §一 写「不得让验证器把自己产生的结果再次证明自己正确」，§九 却写「QA-of-QA → 发现 QA 自身缺陷 → Meta-QA → 改进 QA」，末尾再画 `↺ 回到 L0`。

**Agrippa 三难中，此为 ①无限回归 与 ②循环 之混合，非 ③公理停机。**
**加 `Meta-` 前缀不改变拓扑**——换名字不等于换结构。

此点两侧现已一致：新版已改为治理树 + 反馈支路，且明写「反馈只改方法、规范、验证器版本、适用域、历史影响分析，**不改已观察到的事实**」。**此句收为铁律。**

### 派生禁令

```
① 禁以「再加一层 Meta-」作为回归之解。
② 禁验证链末端指回链内任一节点（含 ↺ L0）。
③ 每条验证链须在册中明写其停机锚编号（A1 / A2 / A3）。无锚者等级封顶 🟠。
④ 「再推一层」须由【新指认之共同上游】触发，不得由「更严谨」之愿望触发。
```

## §五、三处回敬（同型错误与适用域）

### 其一 · 单体独立性是**范畴错误**

「验证器能力矩阵」末栏给 `MD5` → 独立性「高」、`SQL` → 「低」。

**独立性是 pairwise 属性，不是单体标量。**

```
ρ(MD5, SHA-256)          极低   ← 同一读取路径、同一档案句柄、同一 I/O 栈
ρ(MD5, 字节差＝行数)      高     ← 一个靠 I/O，一个靠算术
```

给 `MD5` 一个「独立性：高」，**恰好掩盖了这个差别**；且系凭直觉赋精确等级、无量表无判据——正是本卷 `SC-040` 之同型病。

**须改为对称 n×n 共模矩阵。** 此点两侧现已一致（`I(A,B)` 记法 ＋ Common-Cause Graph）。

### 其二 · ISO 机械叠加违反已锁纪律

已锁标准纪律：多标准适用时按 **权威性 × 适用性 × 证据强度 × 时效性 × 风险重要性** 择用，**禁机械取最严叠加**。

**`ISO/IEC 17025` 之核心机制在此不适用**：其支柱为测量不确定度、计量溯源至 SI、实验室间比对；而 MD5／行数／字节数为**离散确定性读数**——无不确定度，无 SI 可溯。**可借鉴者仅「方法确认」与「技术记录」两节，须明说边界。**

**且原稿漏了手上已锁清单里最贴题的三条**：

| 需求 | **用已锁标准** | 不用 |
|---|---|---|
| 数据质量维度 | **`ISO/IEC 25012`**（固有／系统依赖两类特性） | 自创八维 |
| 数据集质量与生命周期 | **`ISO/IEC 5259`** | — |
| AI 产出／AI 辅助之验证器治理 | **`ISO/IEC 42001`** | 泛称「AI 风险管理」 |
| 风险登记与处置 | **`ISO 31000:2018`** | 另立 NCR 等级 |
| 严重度分级 | **本项目 S1–S4 三轴** | — |

> **红队第八问常备**：我们是在引用标准，还是在自己写规则？
> 自写规则须标 **`T3 工程 · 本项目铁律`**，不得冒充国际标准（T 轴纪律）。

### 其三 · 「三级防线」在单人项目里物理不可得

原稿 §一 写「不能让同一系统同时定义标准、执行检验、证明自己正确」；§十一 却画了一张由**同一主体**（您 ＋ 模型）执行全部三层的图。**职责分离在单人项目里物理上不可得。**

**可行替代不是假装分离，是换独立性来源**——此在复现危机后已有成熟解法，且**您项目已有其二在册**：

```
A2 机械可复算   第三方跑脚本得同一结论，不需信任执行者
A3 预注册       写验证器与用验证器不在同一轮；判据先于数据
（补）时间分离   同一人，不同轮次，判据先写死
```

> **只需把 `E03` 的预注册纪律从复现层推广到验证器层，不必另起 QMS 十三模块。**

## §六、评级维度：四正交维，`INDEP` 移出 min 池

### 收敛理由

十维彼此高度相关——**在验证器身上讲了三轮的共模，套到评级维度上一样成立**。十个相关维度不比四个正交维度多出信息，只多出填表工。

| 正交维 | 核心问题 | 吸收原维度 |
|---|---|---|
| **AUTH 真实性** | 这是不是那个东西 | Authenticity + Traceability |
| **CORR 正确性** | 算得对不对 | Accuracy + Consistency + Completeness |
| **SCOPE 适用域** | 它**不能**回答什么 | Feasibility + Evolvability |
| **INDEP 独立性** | 谁来担保 | Independence + Reproducibility + Reliability |

### ⚠️ `INDEP` 若入 min 池，全册封顶 🟠

木桶取 `min` 已锁。单人项目无第三方复核 → `INDEP` 对**所有**结论恒为 🟠 → **全册无一条可达 🟢**。

**处置**：`INDEP` **不参与 min 运算**，单列为「担保来源」标注栏，取值 `A1` / `A2` / `A3` / `无锚`。

> **独立性是证据的属性，不是结论的分数。**

### 记法

```
AUTH 🟢 ｜ CORR 🟢 ｜ SCOPE 🟢 ｜ 综合 = min(AUTH, CORR, SCOPE) = 🟢
INDEP: A1（数学恒等式）              ← 标注，不入 min
```

## §七、Validator Passport：分级采用

九栏版正确但重。**按复用次数分级，否则一次性 detector 走九栏是负收益。**

| 类别 | 栏位 |
|---|---|
| **一次性**（跑完即弃） | **精简五栏**（下） |
| **复用 ≥ 3 次** | 五栏 ＋ `VP-03 Method`、`VP-08 Version` |
| **进生产／据以判级** | **完整九栏**（VP-01 ~ VP-09） |

### 精简五栏（缺一即封顶 🟠）

```
VALIDATOR-ID        V-R03B-xxx-001
PURPOSE             本器回答什么（一句）
NOT-CAPABLE-OF      本器【不能】回答什么          ← 必填，防越级
NEG-CONTROL-RESULT  已知坏样本之【实际返回值】      ← 非「应返回」
SC-LINKED-DEFECTS   本器过往被 SC 记录之缺陷编号（无则 NONE）
STOP-ANCHOR         A1 / A2 / A3 / 无锚
```

**三条设计要点**：

1. **`NOT-CAPABLE-OF` 必填**——例：`MD5` 能证字节同一，**不能证来源／合法性／业务语义**。此栏防「能力越域」，即自纠册八条形状越界之共同病根。
2. **`NEG-CONTROL-RESULT` 记实返值**——写「应返回 FAIL」是自述；写「喂三行 CRLF 小档，实返 `cr=3`」才是证据。`SC-002` 若做此项，一秒现形。
3. **`SC-LINKED-DEFECTS` 强制回填**——与 §八 矩阵双向锁；无此栏则「缺陷回溯」条款永不触发。

> **`VP-09 Evidence Dependency` 一栏予以采纳**：它是 Common-Cause Graph 之输入，且使共模判定由主观赋值改为**依赖链比对**。列入完整九栏版。

## §八、有限影响回溯（第十五句之落地）

### 规则定稿

> **发现验证器缺陷，必须确定其适用域、生效期间与影响范围，并回溯全部受影响之历史结论；未完成影响分析者，不得维持原等级。**
> **且：只回溯至受影响之历史结论，不重启整个宇宙。**
> **验证器缺陷触发的是【有限影响回溯】，而非【无限 Meta-Validation】。**

### SC 条目必备八栏

```
SC-ID ｜ Root Cause ｜ Affected Validator ｜ Applicability Boundary
Effective Period ｜ Affected Conclusions ｜ Revalidation Status ｜ Disposition
```

> **「已登记为 SC」≠「已了结」。** 登记只证明缺陷被发现，不证明依赖它的结论被重算。

          =  🟠 CONDITIONAL / REVALIDATION REQUIRED

| 类别 | 阶段 |

### 升级之反向条款（必加）

```
V_n  ──▶ 【回归测试】──▶  Re-validation ──▶ Certification
              ↑
   旧版之正／负控制样本，新版须给出【同样】结果
```

```
Upgrade ≠ Certification
Upgrade → Regression → Re-validation → Certification
```

> **升级不自动获得更高可信度；升级本身即被验证对象。**
> **静默改变判据比不升级更危险**——全册历史结论皆建于旧判据之上。

### 退役栏（采纳）

`Retirement Date` / `Reproducibility Status` / `Certification Status` 三栏收入完整版。
**理由**：否则旧验证器会永远活在项目里，接手者不知它已失效。
