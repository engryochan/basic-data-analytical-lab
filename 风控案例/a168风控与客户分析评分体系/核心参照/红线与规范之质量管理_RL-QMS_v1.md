## §一、根本转向：规范性命题不能被验证

| | 验证器（Validator） | 红线（Rule-Line） |
|---|---|---|
| 性质 | **描述性**——读出事实 | **规范性**——禁止行为 |
| 「正确」之意 | 读数与实况相符 | **无真值** |
| 检验方式 | 正／负控制、交叉实现、恒等式 | **不适用** |
| 可问者 | 它读得准吗 | 它管什么、漏什么、误挡什么、何时该退役 |

> **红线没有真值，故不能问「这条红线是不是真的」。**
> **只能问：它的适用域、假阳性、假阴性、依赖与退役条件。**

**推论**：`EAV-QMS` 之 Gate-2（验证器须有正负控制）**不可机械套用于红线**。
红线之对应闸为 **Gate-5 · Rule Gate**（见 §五）。

## §二、红线 Passport（RL-P，六栏必填）

```
RL-ID              RL-00x
STATEMENT          规范原文（一字不改，含原始编号与出处）
SCOPE              适用域：管什么／【不管什么】
FALSE-POSITIVE     假阳性模式：它会挡住什么【本该允许】的        ← 几乎从不被记录
FALSE-NEGATIVE     假阴性模式：它会放过什么【本该挡住】的
DEPENDS-ON         执行本红线所依赖之验证器（若有），及该器之 SC 前科
RETIREMENT         退役条件：什么情形下本红线应当被撤销          ← 最常缺
TRIGGER-LOG        触发历史：触发次数／真阻／误阻
VERSION            版本 ＋ 生效日 ＋ 前身
```

### 三条设计要点

**① `FALSE-POSITIVE` 必填。**
规则系统只记「它挡住了坏东西」，从不记「它挡住了好东西」。
**误阻不被记录 → 误阻永远不会被发现 → 红线只增不减。**

**② `RETIREMENT` 必须在设立当日写死。**
事后补不出来——因为「这条没用了」难以举证，而举证责任在提议撤销者。
**无退役条件之红线，实为永久条款；永久条款须经更高层级批准，不得由单轮讨论产生。**

**③ 语义式优于字面式。**
以具体数值／具体字串写成之红线，**改一位小数即可绕过**。
须写成语义条件，并附当前已知实例，而非以实例代替条件。

### `RL-001` 🔴 **须修订** —— 字面值可能不触发

```
STATEMENT   「0.112 与 Spearman 0.20 不得并列出现」（含转述引用）
```

| 栏 | 内容 |
|---|---|
| **SCOPE** | 防止「预测力天花板」与「模型实测相关」被并列，制造模型已逼近上限之错觉 |
| **FALSE-NEGATIVE** | 🔴 **以字面值定义**。他处曾以 **0.21** 记该相关系数；若实际值为 0.21，**本红线字面不触发**，写 0.21 即合规 |
| **FALSE-POSITIVE** | 连「为何二者不可比」之元讨论亦被禁——而该讨论本身是有价值的 |
| **DEPENDS-ON** | 无（文本层规则） |
| **RETIREMENT** | 未定义 ⚠️ |

**待裁**：实际相关系数究为 `0.20` 抑或 `0.21`？须在源档全文检索定位（且检索器须先过正控制，见 `RL-003`）。

**建议改写（语义式）**：

> 预测力天花板之自相关值，与任何模型层相关系数，**不得并列呈现**，除非同段明写二者分母不同、不可相除、不可作「达成率」。
> 当前已知实例：自相关 0.112；模型层 Spearman 0.20 或 0.21（**待定锚**）。

### `RL-002` 🟠 **须补适用域** —— 与另一强制规则表面冲突

```
STATEMENT   「策略层不得使用 MASE 一名」
```

| 栏 | 内容 |
|---|---|
| **SCOPE** | 仅**策略层**。会员级不受本红线约束 |
| **表面冲突** | 另有已锁纪律：「MASE（Hyndman & Koehler 2006）为所有误差指标之强制，永不用裸 MAE」。**同一指标，一处强制一处禁止** |
| **冲突之解** | 层级不同：会员级 MASE 可算率 9.8%；策略层因样本结构（连胜期、零回撤）不可算。**但 v3 未写出此因** |
| **FALSE-NEGATIVE** | 只禁「MASE 一名」——改称「标准化误差比」即可绕过 |
| **RETIREMENT** | 策略层样本结构改变、MASE 可算率达可用门槛时 |

**建议补句**：

> 本红线之因：策略层因连胜期与零回撤，MASE 分母退化，**不可算**而非**不宜用**。
> 且禁的是**该量**，非该名——改称任何别名同样禁止。

### `RL-003` 🔴 **须加正控制** —— 依赖一个有失效前科的验证器

```
STATEMENT   「外部提供之实测数字，须先在源档全文检索定位；
             零命中者标『来源不可考』并弃用」
```

| 栏 | 内容 |
|---|---|
| **SCOPE** | 外部（含另一模型、另一对话、口述）提供之数字 |
| **DEPENDS-ON** | 🔴 **全文检索器**。而 `SC-029`（`Get-ChildItem -Recurse` 通配降级致计数器零验证力）正是检索器失效之实例 |
| **FALSE-POSITIVE** | 🔴 **致命**：「零命中」有二因——源档真无，或**检索器坏了**。现行写法会把**检索器失效**误判为**来源不可考**，并据以弃用一个可能真实的数字 |
| **FALSE-NEGATIVE** | 检索命中不等于该数在该处**以该义**出现（同名异义已有三例：`bet14`、`mem015`、`κ`） |
| **RETIREMENT** | 不退役——但须随检索器版本同步复审 |

**建议补句（强制正控制）**：

> 援引本红线前，检索器须先以一个**已知存在**之字串验证（正控制）。
> 正控制不过 → 结论为 **`INCONCLUSIVE`**，**不是**「来源不可考」。
> 命中后须另核**语义同一**，防同名异义。

### `RL-004` 🟢 **成立，建议补假阳性栏**

```
STATEMENT   「公开披露 ≠ 可归因」
```

| 栏 | 内容 |
|---|---|
| **SCOPE** | 因果归因命题 |
| **FALSE-POSITIVE** | 可能被过度援引以否定一切关联陈述。**关联可报，归因不可报**——二者须分开，本红线只管后者 |
| **DEPENDS-ON** | 无 |
| **RETIREMENT** | 证据等级达 E5 且识别策略成立时，就该具体命题解除 |

### `RL-005` 🟡 **成立，但须加触发条件** —— 唯一「允许」型红线

```
STATEMENT   「不得把『待外部输入』包装成『待分析』；
             UNRECOVERABLE 本身是合法审计结论」
```

| 栏 | 内容 |
|---|---|
| **性质** | 五条中唯一**允许**而非**禁止**者，故失效方向相反 |
| **FALSE-POSITIVE** | 🟡 **被滥用为提前收工之借口**——「查不到，判 UNRECOVERABLE」 |
| **触发条件（须补）** | **唯走完冻结取证序**（`E05→E01→E02→E04→L01~L10→E03`）**方可援引**。序未走完即援引者，视为违反本红线之前半句 |
| **FALSE-NEGATIVE** | 「待外部输入」与「待分析」之间尚有第三态：「待验证器合格」。该态现无归属 |
| **RETIREMENT** | 不退役 |

**本册应用实例**：Ryo Eng 之「必须坚持的红线」两度为空 →
依 `RL-005` 前半句，记 **⚪ 待外部输入**，**不得转写为「待分析」，不得代拟。**

## §五、`Gate-5 · Rule Gate`

红线不适用 Gate-2（正负控制）。其对应闸如下：

```
新增或修订红线
      ↓
① 有 SCOPE？（含【不管什么】）        ── 无 → 退回
      ↓
② 有 FALSE-POSITIVE 模式？            ── 无 → 退回
      ↓
③ 是语义式而非字面式？                ── 否 → 退回
      ↓
④ 依赖之验证器已过正控制？            ── 否 → 该红线降为 ADVISORY
      ↓
⑤ 有 RETIREMENT 条件？                ── 无 → 须更高层级批准为永久条款
      ↓
⑥ 与现行规范无语义重复／冲突？        ── 有 → 先走 §六 去重
      ↓
   立册，编 RL-ID，记生效日
```

## §六、规范增生：本体系当前最大之未登记风险

### 现况盘点

| 规范类别 | 数量 | 趋势 |
|---|---|---|
| 口诀 | 4 → 6 → 15 → **拟 23** | 持续增长 |
| 红线 | 5 | 持平 |
| 自纠册 SC | **41**（含 033~041 提案） | 持续增长 |
| 母标准项 | 60 | — |
| 三轴 | T4 × L9 × S4 | — |
| 闸门 | 十闸 ＋ 六域 ＋ 拟增 Gate-1~5 | 增长 |
| 机制树 | 六枝 | 冻结 |

### 🔴 核心指认

> **口诀第一句是「口径宗精简」。**
> **而口诀本身已由四句增至拟二十三句。**
> **口诀违反了自己的第一句。**

**风险机制**：规范长到接手方无法内化 → 无法内化之规范 = 不存在之规范 →
**但它制造了「有治理」之错觉，故比没有规范更危险。**

### 首刀应是去重，不是增补

**把 QMS 套用于规范体系，第一个产出不该是新规则，该是语义去重与冲突检测。**

```
① 语义聚类     把二十三句口诀按【所防之失效模式】归类，非按提出时序
② 合并同类     同一失效模式之多句，合并为一句，保留最强表述
③ 冲突裁决     互斥者裁定优先序，或标注适用域使其不再互斥
④ 退役标注     已被更强规则涵盖者，标 SUPERSEDED-BY，不删除（保留历史）
⑤ 分层         【铁律】（违之即废）／【纪律】（须记录例外）／【建议】（可裁量）
                现行二十三句混杂三层，接手方无从分辨轻重
```

**估计**：二十三句可压至**十二句以内**而不失效力。

### 增生监控指标（建议纳入星级派生）

```
规范总条数
接手方内化成本 ≈ 总字数 ÷ 平均阅读速率
每条之触发次数（零触发者为退役候选）
冲突对数
未标退役条件之条数比例        ← 现为 100%
```
