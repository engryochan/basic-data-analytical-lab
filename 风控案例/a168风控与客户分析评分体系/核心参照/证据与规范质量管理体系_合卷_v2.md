## §三、停机定理与三锚

```
① 无限回归  L8、L9…      → 永不落地
② 循环      L7 ↺ L0      → 自证
③ 公理停机  终止于锚      → 唯一可行
```

**三锚不是绝对不可验证的公理，而是当前验证链的终止条件。**
其正当性不在「不可置疑」，而在 **因果不相交**——锚之失效路径与被检对象之生成路径无共同上游（d-分离）。

| 锚 | 与被检对象之因果关系 | 实例 |
|---|---|---|
| **A1 数学恒等式** | 算术不经被检对象之生成路径 | `字节差=行数`；`4096+n×65536`；`181×100,000＋39,550` |
| **A2 机械可复算** | 第三方跑同一脚本得同一结论 | 本卷 §〇 往返一致检验 |
| **A3 预注册** | 判据时间序上先于数据 | `E03`「n=3 固定、禁 optional stopping」 |

```
L0 被检对象 →[L1 业务验证器]→ L1 结果 →[L2 独立交叉]→ A1/A2/A3 之一 → STOP → 等级

✕ 禁 L2→L3→∞      ✕ 禁 L2 ↺ L0      ✓ 许「发现缺陷 → 有限影响回溯 → 重验」
```

**派生禁令**：① 禁以「再加一层 Meta-」解回归；② 禁验证链末端指回链内节点；
③ 每链须明写停机锚编号，无锚者封顶 🟠；④ **「再推一层」须由【新指认之共同上游】触发，不得由「更严谨」之愿望触发**。

## §四、Passport 统一骨架（两册各有一套，本卷合一）

**验证器与红线共用骨架，只标差异栏。**

| 栏 | 验证器（V-） | 红线（RL-） |
|---|---|---|
| `ID` / `VERSION` | ✅ | ✅ |
| `PURPOSE` / `STATEMENT` | 本器回答什么 | 规范原文（一字不改） |
| **`NOT-CAPABLE-OF` / `SCOPE`** | 本器**不能**回答什么 | 管什么／**不管什么** |
| `NEG-CONTROL-RESULT` | 已知坏样本之**实际返回值** | ❌ 不适用（规范无真值） |
| **`FALSE-POSITIVE`** | 误报模式 | **会挡住什么本该允许的** ← 几乎从不被记录 |
| `FALSE-NEGATIVE` | 漏报模式 | 会放过什么本该挡住的 |
| `DEPENDS-ON` | 上游依赖链（Common-Cause 输入） | 所依赖之验证器 ＋ 其 SC 前科 |
| `SC-LINKED-DEFECTS` | ✅ 强制回填 | ✅ |
| **`RETIREMENT`** | 退役条件 | 退役条件 ← **最常缺** |
| `STOP-ANCHOR` | A1/A2/A3/无锚 | ❌ 规范无锚 |

### 四条设计要点

1. **`NOT-CAPABLE-OF` / `SCOPE` 必填** —— `MD5` 能证字节同一，不能证来源／合法性／业务语义。防「能力越域」，即八条形状越界之共同病根。
2. **`NEG-CONTROL-RESULT` 记实返值** —— 写「应返回 FAIL」是自述；写「喂三行 CRLF 小档，实返 `cr=3`」才是证据。
3. **`FALSE-POSITIVE` 必填** —— 规则系统只记「挡住了坏东西」，从不记「挡住了好东西」。**误阻不记录 → 永不被发现 → 红线只增不减。**
4. **`RETIREMENT` 须在设立当日写死** —— 事后补不出来：撤销之举证责任在提议者，而「这条没用了」几乎无法举证。

### 分级采用（防一次性 detector 走全套之负收益）

| 类别 | 栏位 |
|---|---|
| 一次性 | ID / PURPOSE / NOT-CAPABLE-OF / NEG-CONTROL-RESULT / STOP-ANCHOR |
| 复用 ≥3 次 | ＋ METHOD / VERSION / DEPENDS-ON |
| 进生产·据以判级 | 全栏 ＋ 独立交叉 ＋ 版本锁 |

### 升级之反向条款

```
V_n ──▶【回归测试：旧版正／负控制样本，新版须给出同样结果】──▶ Re-validation ──▶ Certification
Upgrade ≠ Certification
```

```

QG-2 验证器闸 缺 NOT-CAPABLE-OF / 正负控制 / 版本 / 失效史 → 不具 GREEN 资格

QG-4 变更闸   验证器变更 → 旧结论自动进入 IMPACT REVIEW
              禁「新版跑过，故历史结论继续有效」
QG-5 规范闸   新增或修订红线须依次过：
              ① 有 SCOPE（含【不管什么】）      ── 无 → 退回

              ⑤ 有 RETIREMENT 条件              ── 无 → 须更高层级批为永久条款

```

> **`QG` 不适用 `QG-2` 于红线**——规范无真值，无正负控制可跑；红线走 `QG-5`。

## §七、评级：四正交维，`INDEP` 移出 min 池

| 维 | 核心问题 | 吸收 |
|---|---|---|
| **AUTH** | 这是不是那个东西 | Authenticity + Traceability |
| **CORR** | 算得对不对 | Accuracy + Consistency + Completeness |
| **SCOPE** | 它**不能**回答什么 | Feasibility + Evolvability |
| **INDEP** | 谁来担保 | Independence + Reproducibility + Reliability |

**十维不是十个自由度**——在验证器身上讲过的共模，套到评级维度上一样成立。

**`INDEP` 不入 `min` 运算**：单人项目无第三方复核 → 若入池，`INDEP` 恒 🟠 → **全册无一条可达 🟢**。
改为「担保来源」标注栏，取值 `A1`/`A2`/`A3`/`无锚`。

> **独立性是证据的属性，不是结论的分数。**
> **且独立性论两两（`I(A,B)`），不论单体**——`ρ(MD5,SHA-256)` 极低（同一 I/O 栈），`ρ(MD5,字节差=行数)` 高。

> 预测力天花板之自相关值，与任何模型层相关系数，**不得并列呈现**，

**乙-2 · 比例原则挂 `severity`**

| 命题 severity | 验证途径要求 |
|---|---|

**乙-3 · 独立性论两两，不论单体**

> 独立性为 pairwise 属性 `I(A,B)`，**无单体定义** `I(A)`。
> 禁写「MD5 独立性：高」。须以对称 n×n 共模矩阵表达，输入为各器之 `EVIDENCE-DEPENDENCY`。
> 例：`ρ(MD5, SHA-256)` 极低（同一 I/O 栈）；`ρ(MD5, 字节差=行数)` 高（一靠 I/O，一靠算术）。
