评分相关数据表

评分与用途（一）

这三件套SQL脚本的核心目标，是构建一个以会员经济价值与风险为中心的风控数据仓库。它并非生成某几张简单的报表，而是将原始杂乱的行为数据，转化为一系列可供业务决策使用的“评分卡与证据表”。

通过对脚本中注释和代码逻辑的梳理，可以提炼出以下核心数据表及其业务定义、用途和揭示的经济效应：

🎯 核心经济效应评估表：会员价值与风险的最终裁决

  • 表名: S01_player_score.csv (会员评分表)
  • 业务定义: 这是整个系统的核心输出表，为每个会员生成一个全面的画像，整合了其经济贡献、风险水平和行为模式。它是平台进行精细化运营和风险处置的最终依据。
  • 用途: 用于会员分层（如VIP等级）、风险定价、营销活动目标人群圈选，以及作为风控决策引擎的输入，决定是否对某会员进行干预（如限额、停用）。
  • 经济效应: 此表旨在量化每个会员的 “净经济价值（residual_b）” 。平台通过此表可以清晰地识别出谁是核心利润贡献者（residual_b 为正且高），谁是亏损源（residual_b 为负），以及谁是潜在的高风险套利者。这为平台优化营销预算、制定差异化留存策略、以及实施精准风控提供了数据基础。

🎲 运营实体评估表：荷官与代理的绩效与风险

  • 表名: S02_dealer_score.csv (荷官评分表)

  • 业务定义: 对荷官这一运营实体进行多维度的绩效与风险评估。它不仅关注荷官带来的流水（在桌洗码量），也关注其服务效率（节奏稳定度）和潜在的操作风险（特定玩家复现率）。

  • 用途: 用于荷官排班管理、绩效评估，以及识别可能与特定玩家存在不当关联的荷官。

  • 经济效应: 此表用于优化人力成本和提升运营效率。一个“节奏稳定”的荷官能带来更流畅的游戏体验，可能吸引玩家更长时间的游戏，从而间接提升平台收入。同时，识别“特定玩家复现率”过高的荷官，可以有效防范荷官与玩家合谋作弊的风险，保护平台资产。

  • 表名: S03_agent_score.csv (代理评分表)

  • 业务定义: 对代理（即发展下线玩家的渠道）进行综合评估。

  • 用途: 用于代理渠道的绩效管理、佣金结算和风险监控。

  • 经济效应: 代理是平台获取新用户的重要渠道，但也是欺诈和套利的高发区。此表帮助平台甄别优质代理与高风险代理，优化渠道成本，防止代理通过“刷流水”等方式套取高额佣金。

⚖️ 风险识别与处置表：从异常检测到干预措施

  • 表名: EV01_disposal_events.csv & EV02_member_disposal.csv (处置事件与会员处置表)

  • 业务定义: 记录平台对会员进行限额、停用、状态变更等风险干预操作的详细日志。

  • 用途: 用于审计风控操作、评估处置措施的有效性（例如，处置后该会员的损失是否减少），以及构建因果推断模型（如 PI01_treatment_delta_member.csv）。

  • 经济效应: 这些表量化了风控措施的“止损”效果。通过对比处置前后的会员行为（PI01_treatment_delta_member.csv），平台可以评估每次干预是否成功降低了风险，从而优化风控策略，减少坏账和欺诈损失。

  • 表名: K01_risk_feature_matrix.csv & P0C** 系列 (风险特征与标签检验表)

  • 业务定义: 一系列用于识别特定风险模式的中间表和检验表，如同IP多账户（C08_subnet_all.csv）、对打（C06_hedge_pairs.csv）、尾段投注（P11_阿泽尾段投注总帐.csv）等。

  • 用途: 作为风险模型的原材料，为 S01_player_score.csv 等最终评分表提供底层特征。

  • 经济效应: 这些表旨在发现并量化各种作弊和套利行为对平台造成的直接经济损失。例如，通过对打（Hedging）套取返水（Rebate），平台损失的不仅是返水金额，还有因此产生的无效流水。

🔍 证据与刻度层：确保决策的科学性与可靠性

  • 表名: 所有表中包含的 evidence_flag, evidence_rate, hold_ci_halfwidth_approx 等字段。
  • 业务定义: 这些字段并非直接用于决策，而是为决策提供证据等级。它们标明了某个评估结果（如某会员的ROI）的统计可信度。例如，evidence_flag 为 THIN_ROUNDS 表示该会员局数太少，其评分不可靠。
  • 用途: 防止基于少量样本的误导性决策。它强制风控人员在进行处置时，必须参考证据等级，避免误伤正常玩家或放跑真正的高风险分子。
  • 经济效应: 这是整个风控体系的“质量保障层”。它确保了基于数据做出的决策（如冻结账户、调整限额）是稳健和可靠的，从而避免了因错误决策导致的客户流失（误杀）和财务损失（漏杀）。

💎 总结

这三件套SQL脚本构建的是一套逻辑严密、层层递进的风控数据仓库。其最终目的，是通过对会员、荷官、代理等核心实体的深度量化，回答几个关键的业务问题：

  1. 谁在为我们赚钱？ -> S01_player_score 的 residual_b (净利)。
  2. 谁在让我们亏钱？ -> S01_player_score 的 residual_b (净亏) 和各类风险特征表。
  3. 我们的运营是否高效、合规？ -> S02_dealer_score 和 S03_agent_score。
  4. 我们的风控措施是否有效？ -> PI01_treatment_delta_member 等处置效果评估表。

整套脚本的最终输出，就是为平台管理层提供一份关于 “平台经济健康度”的全面诊断报告，使其能够基于数据，做出更明智的、能直接提升净利润和降低风险的业务决策。

您提供的是一份数据输出文件目录清单（共137项），而非SQL脚本本身。这份清单定义了每个CSV文件（即查询输出）的业务口径、粒度、适用性和经济意义。下面我将基于清单信息，系统梳理与平台经济效应、收入、增益直接相关的核心表，并说明它们如何支撑待审核的经济指标。

    • PRIMARY —— 核心决策表（如会员评分、尾段分析）

    • REFERENCE —— 参考对照（如平台日度汇总）
    • SUPPORT —— 辅助支持（如产品维度）
    • FACT_BASE —— 事实基础表（无商业判定，仅供底层数据）
    • DICTIONARY —— 字典元数据
    • NOT_FOR_DECISION —— 不用于最终决策（通常因粒度或口径问题）

📈 三、这些表如何支撑“待审”的经济效应？

清单中明确设计了一套逐层归因的经济指标体系，主要通过以下字段体现：

  • 核心利润指标：residual_b（扣除退水和代理成本后的平台净利）、ngr（净游戏收入）、profit（会员净输赢）等，在 A_anchor 和 B01_bt_panel 等表中均有输出。
  • 代理成本：通过 agent_cost（基于五级代理占成）计算，并在多个表中分解为 agent_cost_lv1~lv5，用于渠道增益分析。
  • 近期 vs 非近期：通过 x_rec 旗标区分窗口内近期活动，并计算 roi_recent、stake_ramp 等，用于边际增益变化监测。
  • 风险调整：economic_value（百分位排名）和 action_priority（A/D/E分类）直接用于待审处置优先级，依据就是平台净利贡献。

此外，清单中 net_margin=OK 的表（如 P13_personal_entry、S01_player_score）均包含上述核心字段，是经济效应归因的直接来源。

🧩 四、关于“索引”的理解

清单中并未明确提到“索引”，但每个表都设计了 audit_rn（全局观测编号）和 batch_id（分批号），这相当于行级索引，用于： - 逐行对账（与审计版一致） - 分批导出（每批10000行） - 确保数据完整性（无重复、无缺口）

这些字段是 REDTEAM 裁定的四锁之一，属于审计基础设施，不参与业务计算。

三、数据表体系的价值闭环

┌─────────────────────────────────────────────────────────────────────────────┐
│                        137张表的价值传递链                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【事实层】E事实基表（#133-#137）                                           │
│      ↓ 提供最细粒度事实                                                    │
│  【特征层】A风险识别（44张）+ B会员画像（12张）+ C平台经营（20张）           │
│      ↓ 提取风险特征与行为画像                                              │
│  【决策层】S01会员评分 + S02荷官评分 + S03代理评分                          │
│      ↓ 输出可执行的风险评分与排序                                          │
│  【验证层】D处置因果（26张）+ P0C标签检验（#038-#043）                      │
│      ↓ 验证处置效果，确保模型不泄漏                                        │
│  【基建层】F元数据字典（27张）                                              │
│      ↓ 保障全链条的数据质量与口径一致性                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

核心经济价值体现在三个层面：

  1. 止损价值：风险识别表（对冲、尾段、IP聚集、同桌团伙）直接量化各类作弊和套利行为对平台GGR的侵蚀，是风控止损的依据。

  2. 增效价值：会员评分表（S01）实现精细化运营——识别高价值会员（D档）予以留存激励，识别低价值/高风险会员（A档）予以复核或处置，优化营销资源配置。

  3. 合规价值：责任博彩表（PH0_8r1/8r2）满足合规监管要求；元数据字典（#130-#132）确保数据可审计、可追溯。
