## 一、证一 —— 可执行行**逐字节**相同（最强的一证）

把两版各自的「含可执行内容之行」按原顺序取出（**连行尾注释一并保留，不做任何归一化**），
逐行逐字节比对：

| 版本 | P1 行数 | P2 行数 | 逐行逐字节相同 | SHA-256 |
|---|---|---|---|---|
| 原版审计版 | **41,191** | **41,191** | **是** | `f1600542a58bf6437cdd0a840bd9c24255fd28b8b98ada4b5764a2199eb55ea4` |
| 分批作业版 | **41,836** | **41,836** | **是** | `6c8adb8237729abb6a08777094e49cc3e53b573d4a4c6e72422aeb92ca1a3611` |

⇒ 两版之差，**全部落在「纯注释行」与「空行」上**。连带着一个更强的事实：
**代码行的行尾注释也一个字都没动。** P2 所改者，只有独立成行的注释、空行与段落次序。

## 四、这一结果的**准确含义**（不可多读，也不可少读）

**可以断言的（OBSERVED ＋ 逻辑蕴含）：**

> 提交给 StarRocks 的 SQL 文本，P1 与 P2 **逐字符相同**。
> 因此，**任何输出差异都不可能归因于本次 P2 补丁**——补丁未改动一个可执行字符。

**不可断言的（本次未做，且我做不到）：**

> 我**没有**、也**无法**执行这 129 条查询。本环境无 StarRocks 连接。
> 「跑一遍 P1、跑一遍 P2、逐行 diff CSV」这件事，本次**一次都没做过**。
> 依先生自订铁律 ——「工具自报成功 ≠ 证据已 VERIFIED」——
> 我只把静态证据摆到 OBSERVED，不把它冒充为实测。

**一个必须点破的推论：**

既然两版可执行文本**逐字节相同**，那么先生所设想的实验

```
跑 P1 → 得 CSV_A
跑 P2 → 得 CSV_B
diff CSV_A CSV_B
```

在物理上**等同于把同一条查询跑两遍**。
⇒ 该实验**对「补丁是否改变结果」这一问题零分辨力**——因为在文本层面已无差可辨。
⇒ 它实际测量的是**引擎自身的可复现性**，也就是 W-61 · D-3 那件事。
   这个实验有意义，但它回答的是另一个问题，先生须知其所测为何。

## 五、若仍要做实测，须知的两件事

### 5.1 实测**当前跑不动**

先生要核验的第一件（#002 `B01_bt_panel.csv`）在 2026-08-30 已两次 OOM，一批都没跑完。
⇒ **「逐件实测输出」这件事，本身正被它要验证的那个内存问题挡住。**
⇒ 正确次序仍是：**R0（量 BE）→ R1（落盘一次）→ 再谈逐件实测**。
   落盘之后，比对可完全在库内做，不必导 CSV：

```sql
-- 用同一段文本各物化一次，然后双向差集，两个数皆须为 0
SELECT COUNT(*) AS only_in_A FROM (SELECT * FROM T_A EXCEPT SELECT * FROM T_B) x;
SELECT COUNT(*) AS only_in_B FROM (SELECT * FROM T_B EXCEPT SELECT * FROM T_A) x;
```

### 5.2 实测有**已知的假阳性通道**（D-3），须先设对照组

全包 129 件中：

| 构造 | 涉及件数 |
|---|---|
| 含 `NTILE(…)` / 输出 `vip_tier`（排序键单列非唯一 ⇒ 并列分档不确定） | **128** |
| 含 `PERCENTILE_APPROX`（TDigest 依分片与合并次序） | **128** |
| **两者皆无、可直接以 CSV MD5 干净对比者** | **仅 1 件 —— #078 `S03_agent_score.csv`** |

⇒ 对其余 128 件，即使 SQL 文本一字不差，两次执行**也未必**在这两类列上逐位重现。
⇒ 故实测**必须带对照组**，否则无从归因：

| 组别 | 内容 | 读法 |
|---|---|---|
| **对照** | 同一份 P1 跑两遍 | 若此处已出现差异 ⇒ 差异属引擎，与文本无关 |
| **处理** | P1 一遍、P2 一遍 | 差异集若**不超出**对照组，则无新增差异 |

⇒ 判据分两族：
- **必须逐位相同者**：A 族（和/计数）、B 族（确定比率）、`PERCENT_RANK` 各列、`audit_rn`。
  此族但凡出现一处差异，即为真问题，须立刻停手回查。
- **允许落在对照组范围内者**：`p25/p50/p75/p90/p95/p99`、`p50_valid`、`p50_profit`、`vip_tier`。
  此族差异**不构成对 P2 的指控**，而是 D-3 之实证材料，应据以推进落盘方案。

> 附带一提：`audit_rn` 之确定性对 #002 已当场证成——其 16 键含 `member_id` 与 `bet_date`，
> 而该件粒度正是 `GROUP BY member_id, bet_date`，排序键构成全序。
> 其余 128 件之排序键唯一性未核，登记为 **D-8**，正是此族判据能否成立的前提。

## 六、结论

| 问题 | 回答 |
|---|---|
| P1 与 P2 每个函数的输出是不是一模一样？ | **是。** 且理由不是「测了没差」，而是**「提交的 SQL 逐字符相同，无差可生」**——279 项静态判据全数通过，无一例外。 |
| 这是不是「实测」？ | **不是。** 是静态证明，且**强于**抽样实测：抽样只覆盖被跑到的那几批，静态证明覆盖全部 139 条语句之全部 token。 |
| 那还要不要跑实测？ | **要，但目的不同。** 它测的是引擎自身可复现性（D-3），不是补丁。且**须先解决内存**，并**须带对照组**，否则读不出结论。 |
