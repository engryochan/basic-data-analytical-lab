## 五、铁律与纪律（务必带入新对话）

### 执行纪律

```
① SET 语句必须【一行一跑】，用零注释的 Z00C 文件，不要从聊天复制带 -- 的版本
② 跑前按 Esc 确保无高亮选区
③ 复制查询只选 SELECT … ; 为止，分号之后的注释一个字都不要带
   （SPLIT-CHK：报 Unexpected input '<EOF>' 一律先判「提交了纯注释片段」）
④ 会话参数不跨标签页，新标签须重跑 Z00C
⑤ 串行跑，禁止多标签并行（BE 内存共享）
⑥ spill_mode = 'force' 是高风险实验参数，须先确认磁盘余量，绝不作常设
```

### 数据纪律

```
① 先清洗后计算，禁止未清洗数据直接进入计算
② 禁止数据泄露：只用过去预测未来，禁止用未来解释过去
   · 决策端只准用 t 时刻已存在的数据（含筛选条件本身）
   · 评估端的未来量只准计分，不可回流到选人
   · 流失者必须留在宇宙内计 0，禁止幸存者筛选
   · LEAK-CHK：样本外 R² 异常高一律先判泄露
     （百家乐 ROI 样本外 Spearman 实测 0.026，高于 0.1 即可疑）
③ 分区语义须先判定再用（R4-SEMANTIC-01）
④ 列结构须先读后断言（R4-SEMANTIC-02）
⑤ LIMIT 产生样本，样本中不存在 ≠ 不存在
⑥ 硬编码禁令：阈值须数据推导，不得凭空设门槛
   （已 KILL：persistence ≥ 0.5 · lift ≥ 1.2 · 60% 为正 · 0.001% 敞口）
```

### 代码纪律

```
① SQL 只用行注释，禁块注释
② 禁 OFFSET，用 audit_rn 阶梯
③ ID 比较一律 CAST(... AS BIGINT)
④ 除法一律 NULLIF 护零
⑤ 亿行表加窗口函数，投影必须显式最小化，禁用 SELECT *
⑥ SELECT 列表尾部追加列，必须检查前一列是否以逗号结尾
⑦ 机械替换后必须逐件抽样核对，不可生成完就交付
⑧ 六元组验证：文件名 + 行数 + 字节 + MD5 + 行尾 + 编码
```
