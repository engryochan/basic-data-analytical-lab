# HF9-B · 证据分层判据书（MDE 反解）

**日期**：2026-08-27
**性质**：业务判据裁定书 · 待先生批准后生效
**依据铁律**：统计门槛元审计铁律 —— 禁止手写 `n≥30` 等普适样本门槛；最小样本量须**逐指标反解**；MDE 须依 estimand、结局分布、设计效应分别推导

---

## 一、问题的正确提法

`P50=6 / P75=24 / P90=120` 是**分布事实**，不是判据。把分位数直接当门槛，只是把「凭空写 30」换成「凭数据写 120」，业务论证一步未走。

**正确提法**：对每一个指标，反问「在样本量 n 下，这个指标能不能分辨出我们要找的效应？」——**能，才有资格进入结论；不能，就是 UNKNOWN，不得为凑画像而硬判。**

---

## 二、关键分野：**和型指标** vs **率型指标**

| 类型 | 例 | 抽样误差 | 持续性实测 |
|---|---|---|---|
| **和型**（sum / count） | `stake`、`valid_bet`、`n_bets`、`n_rounds`、`rebate_cost` | **无**（是精确计数，不是估计量） | 注额持续性 **0.870** |
| **率型**（rate / ratio） | `hold%`、`roi`、`roi_recent`、`residual_b_rate`、`turnover_multiple` | **有**，随 √n 收敛 | ROI 持续性 **0.026** |

**这两条已锁的实测值，正是本判据书的核心证据**：ROI 的样本外 Spearman 仅 0.026，而注额高达 0.870。

此前的解释是「时间加权对 ROI 类无效」。**本判据书给出更根本的解释：不是 ROI 没有信号，而是在中位数 n = 6 局的样本量下，ROI 的估计值本身就是噪声。**

---

## 三、率型指标的最小样本量反解

百家乐单注回报的标准差 σ ≈ 0.93（庄）～1.00（闲），取 σ = 0.95。
平台实测 hold = 1.4972%，即单注平均回报 ≈ −0.014972。

**要把某会员的 hold 估计到半宽 ±h（95% 置信）：**

`n ≥ (1.96 · σ / h)²`

**要在 80% 功效下检出该会员与平台基准相差 δ：**

`n ≥ ((1.96 + 0.8416) · σ / δ)²`

| 目标精度 | 95% CI 所需 n | 80% 功效所需 n |
|---|---|---|
| ±1.0 pp | **34,670** | 70,837 |
| ±1.5 pp | **15,409** | 31,483 |
| ±2.0 pp | **8,668** | 17,709 |
| ±3.0 pp | **3,852** | 7,871 |

**反过来看现有分位在此指标上的实际精度：**

| 分位 | n | hold 的 95% CI 半宽 |
|---|---|---|
| P50 | 6 | **± 76.02 pp** |
| P75 | 24 | **± 38.01 pp** |
| P90 | 120 | **± 17.00 pp** |
| P95 | 341 | ± 10.08 pp |
| P99 | 2,447 | ± 3.76 pp |

**P90 的会员，其 hold 的置信区间半宽是 ±17 个百分点** —— 而我们要分辨的效应量级是 **1.5 个百分点**。误差是效应的 **11.3 倍**。

⇒ **在 P90 处用 hold / ROI 排序，等同于按噪声排序。**

## 四、覆盖率：能支撑率型结论的会员有多少

依 v1.2 P3 实测分桶：

| n_rounds | 会员数 |
|---|---|
| ≥ 100,000 | 7 |
| 50,000 – 100,000 | 28 |
| 20,000 – 50,000 | 251 |
| 10,000 – 20,000 | 833 |
| **≥ 10,000 合计** | **1,119** |
| **≥ 20,000 合计** | **286** |

| 精度要求 | 所需 n | 达标会员数 | 占 723,442 |
|---|---|---|---|
| ±1.5 pp（95% CI） | 15,409 | **286 ≤ N ≤ 1,119** | 0.040% – 0.155% |
| ±2.0 pp（95% CI） | 8,668 | ≈ 1,119 – 1,400 | ≈ 0.155% – 0.19% |
| ±3.0 pp（95% CI） | 3,852 | 上界 7,234（P99 之上） | ≤ 1.0% |
| 80% 功效检出 1.5 pp | 31,483 | **≤ 286** | ≤ 0.040% |

**结论**：以 hold / ROI 类率型指标做个体风险判定，**对 99.85% 的会员在统计上不成立**。这不是保守，这是算术。

## 五、`evidence_level` 的正确设计：**逐指标、不删人**

### 设计原则

1. **全员保留** —— 723,442 名会员一个不删，宇宙门取消（HF9-B 本体）
2. **逐指标分层** —— 不设单一全局 `evidence_level`，而是**按指标族分列**
3. **和型指标不设门槛** —— 它们是精确计数，不存在「样本不足」
4. **率型指标按 MDE 反解分层** —— 门槛来自上表，不来自分位数
5. **原值必出** —— `n_rounds` / `n_bets` 逐行出列，消费端可自行套用其 MDE

### 建议出列

```sql
n_rounds,
n_bets,

'EXACT'                                          AS evidence_sum,      -- 和型：恒为 EXACT

CASE WHEN n_rounds >= 31483 THEN 'L1_POWERED'    -- 可 80% 功效检出 1.5pp
     WHEN n_rounds >= 15409 THEN 'L2_CI_1P5'     -- 95%CI 半宽 ≤ ±1.5pp
     WHEN n_rounds >=  8668 THEN 'L3_CI_2P0'     -- 95%CI 半宽 ≤ ±2.0pp
     WHEN n_rounds >=  3852 THEN 'L4_CI_3P0'     -- 95%CI 半宽 ≤ ±3.0pp
     ELSE 'L5_INSUFFICIENT' END                  AS evidence_rate,

ROUND(1.96 * 0.95 / SQRT(NULLIF(n_rounds,0)), 6) AS hold_ci_halfwidth,  -- 逐行现算，非硬编码
```

`hold_ci_halfwidth` 是本设计的关键：**它把「这个数字可不可信」直接写在每一行旁边**，消费端无须理解统计学也不会误用。

### 与分布分位的关系

分位数**保留**，但只作「相对位置」描述，**不作证据等级**：

| 分布位置 | 允许的表述 |
|---|---|
| ≤ P50 | 普通基准区 |
| P50 – P75 | 注意区 |
| P75 – P90 | 优先查看区 |
| > P90 | 高优先查看区 |

**且必须同时满足** `evidence_rate ≠ L5_INSUFFICIENT` **才可进入任何率型结论。**
`> P90` 本身**不是**高风险事实。

## 六、对 `参考.txt` 第九、十节的斧正

`参考.txt` 提出 **L0 OBSERVED / L1 PROVEN / L2 STRONGLY_SUPPORTED / L3 HYPOTHESIS / L4 UNKNOWN** 五级。此建议有两处问题：

### 斧正一 · 与已锁的证据四级冲突

本项目已锁定的证据阶梯是 **OBSERVED / INFERRED / UNKNOWN / CONDITIONAL**，且「禁止跨层升级」。`参考.txt` 新增 `PROVEN` / `STRONGLY_SUPPORTED` / `HYPOTHESIS` 三个层级，与之**并存则冲突，替换则推翻已锁裁定**。registry 中同时存在两套互不映射的证据分类法，是审计上的严重缺陷。

**处置**：`参考.txt` 的五级作为**结论强度**（conclusion strength）另立一轴，**不得**命名为 `evidence_level`，也不得替换已锁四级。

### 斧正二 · 混淆了两个正交的轴

`参考.txt` 用「结论强度阶梯」去回答 HF9-B 的问题，但 HF9-B 问的是**主体的证据充分性**（这名会员有多少局，够不够判），二者正交：

```
证据充分性（本判据书）      ×      结论强度（参考.txt 五级）
n_rounds 是否够                    这句话能说多满
      ↓                                    ↓
      └──────────  二者同时满足才可写入商业结论  ──────────┘
```

若以结论强度充当活跃度分层，**HF9-B 的实际问题（哪些会员进哪一档）一个字都没回答**。

### 采纳

`参考.txt` 第十节「`P90 ≠ 高风险事实`，须同时满足结构证据 + 时间稳定性 + 经济敞口」—— **完全采纳**，已并入第五节。

## 七、同局多父（甲型 724 组）的比例裁定

PK2b / PK2c 逐项闭合（724 / 1,498 / 2,178 / 390,114.6808，两条**逐位相同**），甲型成立无疑。但敞口须一并写入裁定：

| 项 | 数值 | 占比 |
|---|---|---|
| 同局多父注单 | 2,178 | **U\* 的 0.001746%** |
| 同局多父注额 | 390,114.68 | **约 0.002967%** |
| 占三节点自身流量 | 2,178 / 663,714 | **0.3282%** |
| `32856` 一节点占 | groups 96.55% · bets 96.05% · stake 95.89% | 高度集中 |

**裁定**：结构事实 `AGENT-GRAPH-01` 成立并入 registry；但**不以 0.0017% 的敞口驱动全包 129 件的路径模型重构**。

`参考.txt` 自己的铁律「不能因为只有 3 个节点就只看节点数量，须看 node × group × member × bet × stake」**双向适用**：既然现在拿到了 stake = 0.003%，同一条铁律要求**不为 0.003% 过度工程**。

**相称的设计**：`chain_key` 保持现状（P1g 已证 2,528 = 2,528 = 2,528 唯一），**新增标记列**：

```sql
CASE WHEN 该注单落在同局多父组内 THEN 1 ELSE 0 END  AS f_multi_parent_round,
```

如此既**不压平事实**（多父被显式标出），又**不重构模型**（零架构风险）。若日后该现象扩大，标记列即现成的监测口。
