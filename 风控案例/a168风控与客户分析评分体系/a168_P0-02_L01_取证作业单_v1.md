## 三、Step 3 · 三钟校准（介入动作，**排在最后**）

**前提**：Step 1 之查询历史已导出落档。

**操作**：记下 Windows 挂钟 `T_win`，随即在 SQL Lab 执行一句零成本查询，然后三边对账。

```powershell
# ① 先记 Windows 时刻（本机 ＋ UTC 并记）
"T_win_local = " + (Get-Date).ToString('o')
"T_win_utc   = " + (Get-Date).ToUniversalTime().ToString('o')
```

```sql
-- ② 立即于 SQL Lab 执行（零成本）
SELECT NOW() AS db_now, UTC_TIMESTAMP() AS db_utc,
       @@session.time_zone AS sess_tz, @@global.time_zone AS glob_tz;
```

```
③ 记下 Superset 查询历史中「这一笔」之 Start time = T_sup
```

**三钟对账表**

| 对 | 差值 | 含义 |
|---|---|---|
| `T_sup − T_win_local` | ⚪ | Superset 显示钟 相对 本机钟之偏移 |
| `db_now − db_utc` | ⚪ | StarRocks session 时区偏移 |
| `T_sup − db_now` | ⚪ | Superset 显示钟 相对 库钟之偏移 |

**预注册判读**

| `T_sup − T_win_local` | 判 | `17:30:20` 换算为本机时 |
|---|---|---|
| ≈ 0 | 🟢 Superset 显示 = 本机时区 | `2026-08-12 17:30:20`（本机） |
| ≈ −8h | 🟢 Superset 显示 = UTC | `2026-08-13 01:30:20`（本机） |
| 其他固定值 | 🟢 记录该偏移，据以换算 | 依实测 |
| 不稳定 / 不可重现 | 🔴 `TIMEZONE UNRESOLVED` | **`17:30:20` 维持未定时区，一切时序推论继续冻结** |

> **效力上限**：本校准所测者为**今日**之显示钟。若 Superset 配置或浏览器时区在 08-12 之后曾变更，则今日之偏移不可直接外推至 08-12。**须另查配置变更记录；若不可查，该外推标 INFERRED，不得标 OBSERVED。**

## 四、换算之后立即须复核的一件事

时区一旦钉死，须回头复算 `L05` 与 `L01` 之时序关系——**但只复算时序，不作因果**：

```
查询执行   17:30:20（换算后）
CSV mtime  2026-08-12 21:04:36（本机时，已知）
        ↓
二者先后关系  ⚪ 待换算后确定
```

**硬锁**：先后关系确立 ≠ 因果关系确立。前者只决定哪些假设**在时序上不可能**，用于**排除**，不用于**指认**。
