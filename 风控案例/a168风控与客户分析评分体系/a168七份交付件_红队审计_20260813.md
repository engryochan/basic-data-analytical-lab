### A-01 · Wilson 反解得不出 n ≥ 30，且同节代码会当场推翻正文

**所在**：`商业方案.qmd` §sec-stability「样本门槛统一纪律（2026-08-12 立为常设）」

**文档原话**：

> 比例型判据（胜率、占比、对打率、同桌率、`late_share`）——
> 以 **Wilson 95% CI 宽度 ≤ 0.15** 于 $p=0.5$ 最不利处反解，得 **n ≥ 30**。

**现算复核**（Wilson score interval，$z = 1.95996$，$p = 0.5$）：

| n | 5 | 10 | 20 | **30** | 50 | 100 | 167 | 200 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| CI 宽度 | 0.6517 | 0.5268 | 0.4014 | **0.3369** | 0.2671 | 0.1923 | **0.1500** | 0.1373 |

- 宽度 ≤ 0.15 所需最小 $n$ = **167**（朴素 Wald 为 171）。
- $n = 30$ 的实际宽度为 **0.3369**，是标称目标的 **2.25 倍**。
- 纵使把 0.15 读作**半宽**（即宽度 ≤ 0.30），所需 $n$ 仍为 **39**，仍非 30。

**故：无论何种读法，该反解都得不出 30。**

**更要命的是同节的代码会自己拆穿它。** §sec-stability 的 `#| label: wilson` 代码块：

```r
判定 = ifelse(!is.na(hw) & hw <= 0.15, "✅ 可用", "⛔ 过宽")
```

对 `c(5,10,20,30,50,100,200)` 逐个现算。按上表，该表渲染出来将是
**n = 5…100 全部「⛔ 过宽」，仅 n = 200 判「✅ 可用」**——
与紧邻其下的「得 n ≥ 30」正文**正面对撞**。

**影响面**（该门槛被引作依据之处）：

```
R-01  late_share ≥ 0.70 三闸
R-02  同桌率 / 对打率 分层（20%/30%/50%、62%/75%/90%/96%）
R-03  win_rate、n_rounds_eff ≥ 30（A-17 SQL 的 eligibility_min_n = 30 硬写在 SELECT 里）
尾段  §5.4 候选组合的最小尾段局数 10/20/30/50/100
```

且文档自陈「历次交付件十条门槛中**九条未说明依据**，唯此一条有统计推导」——
**现在这一条也没有了**。全部十条门槛目前皆属业务折中，无一条具统计推导。

**处置**：
1. 立即把「得 n ≥ 30」改为实测值。若坚持宽度 ≤ 0.15，则 **n ≥ 167**；
   若 167 在业务上不可行，则须**明写实际接受的宽度**（n = 30 对应 ±0.168）
   并把它当作业务折中申报，不得再称「统计推导」。
2. `eligibility_min_n = 30`、`eligibility_rule` 两列的字面量须随之改，
   否则导出件会带着一个自证有误的口径锁四处流通。
3. 比例型与金额型的分野（文档已立）保留，此条无误。

### A-03 · R-03 的 Z 检验：基准取自注单层、检验做在局层，且均值与分母取自不同总体

**所在**：`商业方案.qmd` 归档 A-17（§sec-sql-a-17），SQL 主体

**缺陷 ①：基准与检验不同粒度。**

```sql
side_base AS (                          -- 注单层
  SELECT bet_side,
         SUM(CASE WHEN game_pnl > 0 ...) / NULLIF(SUM(CASE WHEN game_pnl <> 0 ...),0) AS p_base
  FROM ord WHERE is_sentinel_dealer = 0
  GROUP BY bet_side
)
```

`ord` 是**注单**粒度，故 `p_base` 是**每注**的胜率。

```sql
pr  AS ( ... GROUP BY member_id, dealer_id, is_sentinel_dealer, round_key )   -- 局层
pd  AS ( ... SUM(CASE WHEN p.game_pnl > 0 THEN 1 END) AS n_win, ... )         -- 局层计胜
```

而 `n_win / n_dec` 是**局**层的胜负计数（局内多注先 `SUM(game_pnl)` 再判正负）。

对**同一局押多方向**的玩家（押庄兼押和、庄+龙宝、闲+对子……），
该局净 `game_pnl > 0` 的概率**不等于**各注注额加权后的每注胜率。
Z 分数的零假设 $p$ 因此被系统性错设，且错设方向随该玩家的押注组合而变——
不是随机噪声，是可随人变号的偏差。

**旁证**：《百家乐同桌对打风控分析报告》§八 对同一现象的处理是
`HAVING COUNT(DISTINCT bet_type) = 1`，即**直接排除混合方向的玩家局**，
并在 §11.1 专门说明理由。**同一平台族内，两份交付件对同一问题的处置相反。**

**缺陷 ②：均值总体 ≠ 分母总体。**

```sql
pd:  AVG(p.p_base_round_w) AS p_base_mix_w      -- 对 n_rounds_eff 行取均值
Z :  (n_win - n_dec * p_base_mix_w) / SQRT(n_dec * p_base_mix_w * (1 - p_base_mix_w))
```

`p_base_mix_w` 遍历**全部** `n_rounds_eff` 局取均值，
而 Z 式乘的是 **`n_dec`**（决胜局）。二者相差的正是 `game_pnl = 0` 的**退还局**——
而按 §sec-settle，退还局恰恰**只**出现在庄闲（Draw No Bet），其 `p_side ≈ 0.5068`。
故非决胜局被系统性地以 0.5068 拉动均值，而它们又不进 `n_dec`。

$p$ 偏了，$np$ 与 $\sqrt{np(1-p)}$ 同时偏，Z 的偏移量与该对的和局比例成正比。
**和局多的玩家—荷官对被系统性地推向某一方向**——这正是 Z 榜要辨别的东西。

**正解**：`p_base_mix_w` 须只对**决胜局**求加权均值
（`AVG(...) FILTER (WHERE game_pnl <> 0)` 或在 `pr` 层先标 `is_decisive` 再条件聚合）。

**缺陷 ③（较轻，但须记）：`MAX(bet_side) AS main_side` 仍在。**

归档 A-17 的段首 callout 明写：

> 旧版归档（含 `MAX(bet_side) AS main_side` 与 `COALESCE(s.p_base, 0.5)`）**已废止**

但 `pr` CTE 里 `MAX(bet_side) AS main_side` **原样保留**（`COALESCE(...,0.5)` 确已删除）。
它不再参与基准计算（基准已改注额加权），故当前无害；
但它在 `pr` 层算出后**从未被 `pd` 或最终 SELECT 取用**——是死代码，
且其存在使 callout 的陈述在字面上不成立。任何人 `grep MAX(bet_side)` 都会得到与 callout 相反的结论。
须删，或在 callout 中改述为「其取值已不再参与基准，列本身待清理」。

### A-05 · 商业方案主推的替代口径（D-03R）正落在 v8 明令禁止的路上

`商业方案.qmd` §sec-progress-fail「方案二（D-03R）· 局内下注顺序」：

```sql
PERCENT_RANK() OVER (PARTITION BY round_key ORDER BY bet08) >= 0.80
```

并评为「**方案二更稳健**……分析方推荐方案二为主口径」。

`v8.qmd` §Z-09b 的专门警告：

> **绝不可以「该局实测最末下注秒」当作该局之封盘时刻。**
> 如此则每局最后一名下注者自动被判为「零秒封盘」——所欲测者与所用之尺成了同一物，
> 循环论证。且此偏差与该局热闹程度相关，而热闹程度又与玩家类型相关，
> 构成系统性混淆，非随机误差，事后无从校正。

`PERCENT_RANK` 不用秒数，但**病灶同源**：一个玩家是否「尾段」，
由**同局其他人何时下注**决定。冷清局里第二个下注的人 `PERCENT_RANK = 1.0`；
热闹局里同一时刻下注的人可能只有 0.3。而局的冷清程度与桌台、时段、
玩家类型全部相关——正是 v8 所指的系统性混淆。

**附带一处定义—统计量混淆**（与 §sec-r01 自己警告过的那条同型）：
`PERCENT_RANK >= 0.80` 恒定的是**每局最后两成的下注者**，
即尾段人数恒为局内人数的 20%。这使「尾段占比」这个统计量的分母随局内人数浮动，
**跨局、跨桌、跨时段不可比**——而尾段占比恰是需求 §5.3 的核心指标之一。

**处置**：既然 v8 §Z-09c 已把 `W(table_id)` 定为桌台级外生常量，
优先路线应是 `close ≈ bet06 + W(table_id)` 的**绝对相位**，
而非局内相对排序。D-03R 至多作稳健性对照，不宜为主口径。

### A-06 · 哨兵判据「R 侧与 SQL 侧逐字同义」这一声明不成立，且违反自订最高纪律

`商业方案.qmd` 第 908 行（资格分层块注释）：

> 哨兵判据与 SQL 侧 §R03 的 `is_sentinel_dealer` 逐字同义（`eid ∈ {-1, 0, 空}`）。

归档 A-17 的实际 SQL：

```sql
base AS (
  SELECT ..., CASE WHEN TRIM(r.eid) IN ('-1','0') THEN 1 ELSE 0 END AS is_sentinel_dealer, ...
  FROM ranked r
  WHERE r.rn = 1
    ...
    AND NULLIF(TRIM(r.eid),'') IS NOT NULL      -- ← 空 eid 在此被直接删掉
```

- `is_sentinel_dealer` 只判 `{-1, 0}`，**不含空**；
- **空 eid 在 `base` 层就被 `WHERE` 剔除**，根本进不了 L0 事实层，
  遑论被标为 `SENTINEL_DEALER`。

**两项后果**：

1. **违反自订「事实层不删」最高纪律**（§sec-layer-contract，明列为「不可退化条款」）。
   空 eid 的注单在 SQL 源头被静默删除，L0 `r03_full` 里**从来没有过它们**，
   故「L0 全量 8,061,974 行」并非真全量。
2. **R 侧与 SQL 侧的哨兵计数不可能同时成立**。R 侧按 `{-1,0,空}` 统计并写入分层账，
   SQL 侧的 `SENTINEL_DEALER = 243,025` 按 `{-1,0}` 且空已先删。
   §sec-qual-layer 的「L0 行数 / 哨兵行数 / L1 留存率」三栏，
   其分母与 SQL 的分母不是同一个总体。

**旁证支持部分免责**：`v8.qmd` §Z-07 实测，
限 `bet02='101'` 后 `eid = 0` / `bet03 = 0` / `bet39 = 0` / `gametype = 3`
那批各 120,811 笔的「電投網投模式」**全数消失**，
故百家乐范围内 `eid = 0` 很可能为空集，哨兵实际只有 `-1` 一值
——这与 §sec-probe-findings「哨兵只有**一个** `dealer_id`」互证。

### A-07 · 「测试窗互不重叠」这条硬判是假通过

`商业方案.qmd` §sec-purged：

```r

  g <- health[[5]]; L <- health[[4]]; lo <- as.Date(health[[6]])
  c("空窗恒达设定值" = all(g >= gap_expect),
    "训练长度恒定"   = (length(unique(L)) == 1L),

```

`lo` 是各折**测试起日**。`diff(lo) > 0` 只验证「测试起日严格递增」，
**完全没有验证重叠**。

**同一份文档 §sec-fold-contract 自己写着**：

> 步长 1 而测试窗 14，相邻两折的测试窗**重叠 13/14**，折级统计量高度相关

而正文在两千行外承认它们重叠 92.9%。**

**正解**（须比对前折测试**止**日）：

```r
te_hi <- as.Date(health[[7]])
"测试窗互不重叠" = (length(lo) < 2L) || all(lo[-1] > te_hi[-length(te_hi)])
```

改正后该项在甲/乙规格下将**如实判 FALSE**——这正是它应该做的：
重叠不是缺陷（每日滚动是刻意选的），**假装不重叠才是缺陷**。

### B-05 的注记：噪声判伪的量化匹配对 $n$ 的取法敏感

商业方案 §sec-stability 写：

> 固定规则只把订单门槛由 30 提到 50 再到 100，ROI P95 由 38.62% 降至 20.46%，
> 收缩倍数 1.235 / 1.888，与纯噪声预测 1.291 / 1.826 **偏离不足 5%**。

**现算**：38.62/31.27 = 1.2350、38.62/20.46 = 1.8876；
$\sqrt{50/30} = 1.2910$、$\sqrt{100/30} = 1.8257$。**算术无误，结论方向成立。**

**但须注记一处**：此处以**门槛值**（30/50/100）当 $n$，而门槛只是各组 $n$ 的**下界**。
用同一张表的「平均有效投注」（8,704.80 / 17,885.71 / 47,136.12）作 $n$ 的代理，
实际比值为 **2.055×** 与 **5.415×**，则纯噪声预测应为
$\sqrt{2.055} = 1.433$、$\sqrt{5.415} = 2.327$——**大于**实测收缩 1.235 / 1.888。

**这不推翻结论**（实测收缩仍落在纯噪声可解释的范围内），
但「偏离不足 5%」这个精度声明**依赖 $n$ 的取法**，不宜作为定量吻合的凭据。

**建议改述**为：「实测收缩落在纯噪声预测的区间内（以门槛为 $n$ 得 1.29/1.83，
以平均规模为 $n$ 得 1.43/2.33，实测 1.24/1.89 居中），
**故该尾部无须任何『优势』假设即可解释**」——结论不变，措辞不越界。
