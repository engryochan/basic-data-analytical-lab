## 〇、切法斧正（须先裁）

裁示定「采用 A–F，不另拟」＋「每批约 1,000 行只是施工粒度，不是语义边界」。
**实测发现二者互斥**——本包按历史累积成序，非按语义分层成序：

| 行区间 | 主要段族 | 语义层 |
|:--|:--|:--|
| 1–2000 | §Z×64 ＋ 卷首 | **A** 纪律 |
| 3001–5000 | §R01×87 §R03×49 §R02×27 | **D** 风险判据 |
| 5001–6000 | §E02×39 §K01×21 | **E** 经济 |
| **6001–8000** | **§EX×193 §P0×41** | **B** 结构探查 ← **不在第二批** |
| 8001–9000 | §TL×120 | **E** 处置 |
| 9001–10549 | §P12×62 §R01×68 §Z×38 | C ＋ D ＋ **A** 混杂 |

`§EX`（数据源／取数／核验）密集于 6001–8000；`§Z`（纪律）同时见于卷首与卷尾变更记录。
**故「批次名」不能同时承载「连续行区间」与「语义层」——此与已裁之版本宪法冲突同形。**

**处方（循丙案同一原则 · 两轴分离）**：

```
施工批次   批-01 … 批-11    连续行区间，约千行，snap 至语句边界
语义层     A … F            裁示所定，原样保留，每段各标其一
```

每段同携二者（如 `批-04 / 层D`）。**不另造第七种切法**，A–F 原样为语义层，只是不再兼任行区间之名。

## 三、本批三项发现（**皆不在本批施工，仅登记**）

### 发现① · 卷首血统登记表仍指 `v10`（S2 · 血统失锚）

```
a168_取数与核验_SQL总包_v10.sql   本包(料源)   一切数字之唯一出处
```

canonical 已行至 `v11.0.3`，该行仍书 `v10`。
**与 `paths_a168.R` 之 `sql_main` 指针失锚系同一族问题**（该工单在册未销）。
→ 属注释区，可并入 `v11.0.4` PATCH；**本批不施工**。

### 发现② · 卷首「三个 MD5」与现制四锚不符（S3）

卷首列三 MD5（原样／LF／纯代码），而现行验收已用**四锚**（另加纯代码行数）。
且 `VERSION-META-01` 之三层身份（Release／Contract／Impl）尚未写入卷首六元组段。
→ 属注释区，宜并入 `v11.0.4`；**本批不施工**。

### 发现③ · `TABLE_ROWS` 系估计值，未标判级（S3）

`INFORMATION_SCHEMA.TABLES.TABLE_ROWS` 在多数引擎为**统计估计**，非精确计数。
§Z-01 输出列名书「估计行数」已属正确，惟未明书**不得用作分母**。
→ 承 `G-METRIC-02`（六元定义），宜补一句禁令；**本批不施工**。
