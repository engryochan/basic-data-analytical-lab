# 版本编号纪律 v1.0.0

**立册**：2026-08-23（用户令）　**效力**：永久，全项目、全档种、无例外　**置放**：`规范/`

---

## 一、总则

### 一之一 · 三段式

一切版本号一律书作 **`MAJOR.MINOR.PATCH`**，三段皆为非负整数、皆以点号分隔。

$$\text{vMAJOR.MINOR.PATCH}\qquad 0 \le \text{MINOR},\ \text{PATCH} \le 999$$

**每段满 999 方晋一级**：`v1.0.1 → v1.0.2 → … → v1.0.999 → v1.1.0 → … → v1.999.999 → v2.0.0`。

### 一之二 · 禁跳级（本纪律之核心）

**禁由 `vN` 直跃 `vN+1`。** 任一 MAJOR 之晋升，其前必有至少一次 MINOR 或 PATCH 之落地记录；任一 MINOR 之晋升，其前必有至少一次 PATCH 之落地记录（首版 `v1.0.0` 除外）。

理由：跳级即把「若干笔互不同质的改动」压成一次不可拆解的变更。一旦回滚，**无从判断该退到哪一步**；一旦出错，**无从判断是哪一笔所致**。逐级之代价是多写几次变更记录，跳级之代价是整条血统不可追溯。

### 一之三 · 版本号是身份，不是序号

同名不同内容即身份冲突。故：

- **禁追溯改名。** 已在册之旧版号（`v10`、`v11` 之属）一律保留原名，改以**等价声明**接入新制；
- 每一版号须与**六元组**唯一绑定：文件名 ＋ 行数 ＋ 字节数 ＋ MD5(原样) ＋ MD5(LF 归一) ＋ 换行制式 ＋ 编码；
- 旧版一律加 `_superseded` 后缀归档，**禁删**。

## 二、级差判据（机器可验，防主观）

| 级 | 判据（硬） | 典型改动 | 下游 `must=` |
|:--|:--|:--|:--|
| **PATCH**<br>`vX.Y.Z+1` | **纯代码 MD5 不变**（剥离全部注释后逐字节相同） | 注释、文档、排版、判读指引、错别字、状态登记 | 不动 |
| **MINOR**<br>`vX.Y+1.0` | 纯代码 MD5 变；且 **`schema_diff` 为空集**（既有交付件之表头一列不增不减不改名） | 新增段落、新增交付件、新增只读诊断 | 不动 |
| **MAJOR**<br>`vX+1.0.0` | **`schema_diff` 非空集** | 改列名、改列义、删列、改阈值口径、改判词取值域、改窗口、改分组粒度 | **须同步** |

**判定次序（不可颠倒）**：先算纯代码 MD5 → 若不变即 PATCH，判定终止；若变，再算 `schema_diff` → 空集即 MINOR，非空即 MAJOR。

**兜底铁律**：凡下游三档（主方案／精要版／对照本）之 `must=` 清单须随之改动者，**无论改动看似多小，一律 MAJOR**。表头即契约，契约变更无小事。

### 四之三 · 四条红线（REDTEAM 2026-08-23 锁，不可歧义）

1. **不得恢复 `v11.0.0` 为运行基线。**
2. **不得再制造任何 `v11` 无版本号之工作副本**（「hotfix 工作件」第三血统就此绝迹）。
3. **不得跳过 `v11.0.2 → v11.1.0 → v12.0.0`。**
4. **任何声称「当前 v11」之代码、登记、引用、`must=`，均指向 `v11.0.1`**；唯**历史追溯**方得指向 `v11.0.0_superseded`。

**归档 ≠ 失锚。** `v11.0.0` 带完整六元组在册，恰是血统锚本身：

```
v11.0.0（原始档 · 原始 MD5 · 原始登记）→ _superseded
        ↓  PATCH：纯代码 MD5 不变、schema 不变、七处注释纠错（D01–D07）
v11.0.1（当前 canonical · 修订原因在册）
```

### 四之四 · 身份断言须双层（档名 ＋ 内容）

只验档名不足以定身份——**档名可改，内容不可伪**。故一切「当前版本」之断言须双层并用：

| 层 | 断言 | 性质 |
|:--|:--|:--|
| 档名 | 路径含 `v11.0.1`、居项目根 | 必要非充分 |
| 内容 · 整档 | `MD5(原样) = 0ca29917…5b08b8d6` | 定「是哪一版」 |
| 内容 · 纯代码 | `MD5 = ce768c35…66a8c422` | 定「代码有没有被动过」 |

第三条**跨版恒定**（`v11.0.0`／`v11.0.1` 皆同）。将来 `v11.0.2` 落地后，第二条会变、第三条不变——**两条合用即可分辨「正常晋级」与「代码被误改」**。自 `v11.1.0` 起代码 MD5 必变，届时改以 `schema_diff` 为空集作判据。

G-1 与 G-2 皆改交付件 `R01chk_shoe_len_by_table.csv` 之表头，故须与下游 `must=` 清单同步；此即兜底铁律之实例。
