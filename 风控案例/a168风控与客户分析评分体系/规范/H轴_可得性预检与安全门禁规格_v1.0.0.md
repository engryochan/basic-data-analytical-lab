## 〇、立轴缘由与一条前置铁律

业务侧提出「推荐算法／留住会员／赢钱后推荐朋友」之课题。经裁示改称
**`Recommendation & Engagement Layer`**，并要求「强烈伤害指标出现时切 safety mode」。
本册即该门禁之规格。

**前置铁律（本册第一条，先于一切设计）**：

> **H 轴在可得性预检通过之前，不得立册、不得进决策链。**
> 一个测不准的安全门禁，**比没有门禁更坏**——它给出「已经把关过」的错觉，
> 而实际上什么都没挡住。宁可标 `UNKNOWN` 而暂无门禁，不可标 `PASS` 而门禁虚设。

## 二、六条不污染（前五条承裁示，第六条为 R4-E 新增）

1. **风险判定** 只答「风险是什么、证据是什么」；
2. **经济价值** 只答「价值是多少」；
3. **处置** 只答「采取了什么行动」；
4. **结果** 只答「行动之后发生什么」；
5. **推荐** 只答「在安全门禁允许下，什么内容产生可持续价值」；
6. **★ 营销资格（M）只得由 H 轴计算，禁引 V 轴。**

**第六条之所以最要紧**：若 M 引 V，逻辑即成「**高价值 ＋ 高伤害 → 因为他值钱，所以更要推给他**」。
这是整套系统里**唯一一处会主动放大伤害的耦合**，必须在架构层焊死，不能靠人自觉。

**推论**：会员赢钱、输钱、高价值、低价值、介绍朋友、长期留存——
**皆不得反过来篡改其风险事实与伤害事实**。

## 三、H 轴可得性预检（P-H0 ~ P-H3，须逐项探针，禁臆断）

### 三之一 · 现有料源之实况

| 伤害指标族 | 所需源 | 本窗可得性 | 判级 |
|:--|:--|:--|:--|
| 时段异常（深夜、通宵） | `bet06`／`bet08` | ✅ 可算 | OBSERVED |
| 注额爬升（单靴内、跨日） | `bet13`／`bet11` | ✅ 可算 | OBSERVED |
| 连输后加注（追损） | 逐注序列 ＋ `bet17` | ✅ 可算（须逐注排序） | INFERRED |
| 投注频次陡增 | `bet01` 计数 × `dt` | ✅ 可算 | OBSERVED |
| **入金频次／失败入金** | 支付表 | **❌ 不在注单表** | **UNKNOWN** |
| **在线时长／session** | 会话日志 | **❌ 不在注单表** | **UNKNOWN** |
| **自我排除／冷静期** | 会员状态变更 | ◐ `log_mem_change` 或有 | **UNKNOWN** |
| **客服求助／投诉** | 工单系统 | **❌ 不在库** | **UNKNOWN** |

**判读**：**真正的伤害主指标（入金、时长、自我排除、求助）现下几乎全为 `UNKNOWN`**；
可算者皆为**行为代理量**，只能作次级证据。

### 三之二 · 预检四步（次序不可颠倒）

```
P-H0  源表普查：支付／会话／会员状态变更／工单，逐张确认在库与否、粒度、可连接键
P-H1  可连接性：能否以 uid 与注单表对齐；对齐率现算，低于阈值即判不可用
P-H2  时间覆盖：该源之窗口是否覆盖 2026-03-21 ~ 2026-08-06；
      不覆盖者判 NOT_RECOVERABLE（换窗方可），非 UNKNOWN
P-H3  指标可算性：逐指标标 OBSERVED / INFERRED / UNKNOWN / NOT_RECOVERABLE
```

**四步全过，H 轴方得立册。** 任一步未过，H 轴维持 `NOT_ESTABLISHED`，
而 **safety gate 在此期间取最保守设定**（见第五节）。

## 四、R4-A · 窗口不对称：四象限须分轴设窗

裁示之四象限（收入 × 风险）在**同一结果窗**下会系统性偏袒最坏的一格：

$$\text{收入以「日」计} \quad\text{而}\quad \text{伤害以「月」计}$$

短窗内，「收入↑ ＋ 风险↑」会被读成「收入↑ ＋ 风险持平」——**因为风险尚未显形**。
若据此优化，等于**奖励延迟伤害**。

**故约束须绑在前瞻风险，且各轴各设其窗**：

$$\max\ \mathbb{E}\bigl[\Delta \text{NGR}_{30d} + \lambda_1 \Delta \text{Retention}^{\text{healthy}}_{90d} + \lambda_2 \Delta \text{CLV}_{180d}\bigr]$$

$$\text{s.t.}\quad \widehat{\text{Harm}}_{180d} \le \text{Harm}_{\text{limit}}, \qquad \widehat{\text{Risk}}_{90d} \le \text{Risk}_{\text{limit}}$$

**⚠ 139 日窗之硬限**：`180d` 之量在本窗内**结构上不可得**，判 `NOT_RECOVERABLE`。
故当前只能以短窗代理并**显式标注其为代理**，禁以代理量之达标宣称长窗达标。

**四象限之读法锁**：

| | 风险↓ | 风险↑ |
|:--|:--|:--|
| **收入↑** | 🟢 唯一值得优化之格 | 🔴 **禁止优化**——不得因钱多而判优 |
| **收入↓** | 🟡 可接受 | 🔴 最差 |

## 五、Safety Gate（H 轴未立册期间之保守设定）

在 P-H0~P-H3 未全过之前，**门禁取保守侧**：

| 条件 | 处置 |
|:--|:--|
| 任一**可算之行为代理量**触及高位（夜间占比、注额爬升、追损、频次陡增） | **停定向营销、停新 bonus**，转人工复核 |
| 伤害主指标 `UNKNOWN` | **不得**因「测不到」而判为「无伤害」——`UNKNOWN ≠ NO_EVENT` |
| M（营销资格） | 默认 **不发放**；须 H 轴明示放行方得发放 |

**`UNKNOWN ≠ NO_EVENT`** 是本项目既有铁律，于 H 轴尤其要紧：
**测不到伤害，不等于没有伤害。**

## 六、留存须二分（承裁示第九节）

| | 定义 | 计入成功？ |
|:--|:--|:--|
| **Healthy Retention** | 继续使用，且风险与伤害指标未恶化 | ✅ |
| **Harm-driven Retention** | 因刺激／奖励／定向诱导而持续高频 | ❌ |

故正式指标为 **`sustainable_retention_rate`**，非裸 `retention_rate`。
裸留存率**禁作 KPI**——它把两种性质相反的东西加在一起。

**商业上亦然**：伤害驱动之留存不是收入，是**负债**——
以投诉、赔付、牌照风险与流失之形式后置。

## 七、R4-C／R4-D · 推荐与网络价值之两处口径陷阱

### 七之一 · `NetworkCLV` 之重复计数

$$A \to B \to C \quad\Rightarrow\quad C \text{ 同时进 } A \text{ 与 } B \text{ 之网络价值}$$

**须先声明归因规则**，二择一并写死：

- **单归因**：只归首位推荐人；
- **衰减多层**：$w_k = \delta^{k}$，$\delta$ 预注册，逐层衰减。

未声明即禁算——否则网络价值可刷至任意大。
且 139 日窗测不出被推荐人之 CLV，判 **`NOT_RECOVERABLE`**。

### 七之二 · 「赢钱后推荐朋友」之选择偏误

赢家推荐得多，**可能只因赢家是随机抽出的一群人**——
与「`ROI > 0` 命中主体系方差」为同一失效模式。

**正确估计量是因果的**：赢钱是否**导致**推荐？抑或推荐倾向高者恰好落进赢家池？
零假设下亦会观察到相关。**须以准实验（PSM／DID）估计，禁以相关代因果。**

## 八、干预之因果评估（承裁示第五、六节）

$$\Delta\text{Profit} = \text{Profit}_{\text{intervention}} - \text{Profit}_{\text{counterfactual}}$$

处置组 / 对照组分派须**预注册**；结果窗按第四节分轴设定。
并承 `SC-15` 之 **R4-6a 噪声地板**：

$$\text{avoidable\_loss}_{\text{net}} = \Sigma_i \max\bigl(0, \hat\mu_i-\mu_0\bigr)\text{stake}_i - \mathcal{F}_0$$

**净额不显著大于 0 者判 `NO_ACTIONABLE_LOSS`，不得上报金额。**
