# 风控平台第一版权限设计

## 1. 设计目标

第一版采用简单的“用户 + 固定角色 + 页面权限”模式，优先满足风险查询、玩家详情和玩家备注的基本使用需求。



## 2. 用户

用户代表登录风控平台的具体人员。

第一版用户信息包括：

```text
用户账号
工号
角色
账号状态
创建时间
最后登录时间
登录IP
```

账号状态只设置两种：

| 状态 | 说明 |
|---|---|
| 启用 | 可以正常登录和使用系统 |
| 停用 | 不允许登录系统 |

第一版不提供用户删除功能，避免用户被删除后，历史玩家备注无法找到对应的操作人员。

## 3. 角色

第一版设置三种固定角色。

| 角色 | 主要作用 |
|---|---|
| 管理员 | 管理用户并使用平台全部功能 |
| 风控人员 | 查询风险、查看玩家详情和添加玩家备注 |
| 只读人员 | 只能查看风险数据和玩家详情，不能添加备注 |

第一版不支持创建自定义角色，也不支持给单个用户单独配置权限。

## 4. 权限

第一版只设置以下四项权限：

```text
查看风险查询
查看玩家详情
新增玩家备注
管理用户
```

角色与权限对应关系如下：

| 权限 | 管理员 | 风控人员 | 只读人员 |
|---|---:|---:|---:|
| 查看风险查询 | ✓ | ✓ | ✓ |
| 查看玩家详情 | ✓ | ✓ | ✓ |
| 新增玩家备注 | ✓ | ✓ | × |
| 管理用户 | ✓ | × | × |

## 5. 用户管理

侧边栏增加“用户管理”菜单，该菜单仅管理员可见。

管理员可以执行以下操作：

- 新增用户；
- 修改用户工号；
- 修改用户角色；
- 启用或停用用户；
- 重置用户密码。

管理员不能删除用户。

启用状态的用户可以在登录页面输入账号、当前密码和新密码修改自己的密码。新密码至少8位，并同时包含字母和数字。停用用户不能修改密码。

## 6. 不同角色看到的页面

### 6.1 管理员

管理员可以看到：

```text
用户管理
玩家详情
牌靴后段下注
玩家—荷官
同桌对打
```

### 6.2 风控人员

风控人员可以看到：

```text
玩家详情
牌靴后段下注
玩家—荷官
同桌对打
```

风控人员可以在玩家详情中新增玩家备注。

### 6.3 只读人员

只读人员可以看到：

```text
玩家详情
牌靴后段下注
玩家—荷官
同桌对打
```

只读人员不能新增玩家备注，玩家详情中不显示“新增备注”按钮。

## 7. 前端和后端权限处理

### 7.1 前端处理

前端根据用户角色控制菜单和按钮是否显示。

例如，只读人员没有新增备注权限：

```text
玩家详情不显示备注输入框和“新增备注”按钮
```

非管理员用户：

```text
侧边栏不显示“用户管理”菜单
```

### 7.2 后端处理

后端必须再次检查用户权限，不能只依赖前端隐藏按钮。

例如，只读人员直接调用新增备注接口：

```text
后端检查用户没有新增备注权限
返回 HTTP 403
不保存备注
```

非管理员直接调用用户管理接口时，也应返回 HTTP 403。

## 8. 操作记录

第一版只记录两类关键操作：

### 8.1 登录记录

```text
用户ID
用户工号
登录时间
登录结果
登录IP
```

### 8.2 玩家备注记录

```text
备注ID
玩家ID
备注内容
备注人员ID
备注人员工号
备注时间
```

玩家备注第一版只允许新增和查看，不支持修改和删除。

## 9. 第一版暂不实现的功能

以下功能留到后续版本：

- 自定义角色；
- 给单个用户单独勾选权限；
- 按 `source_db` 限制数据范围；
- 按站点限制数据范围；
- 按五级代理限制数据范围；
- 数据导出申请和审批；
- MFA 双重认证；
- 临时授权和权限有效期；
- 角色冲突检查；
- 复杂的操作审计平台。

## 10. 第一版验收标准

### 10.1 管理员

- 可以进入用户管理页面；
- 可以新增用户；
- 可以修改用户角色；
- 可以启用或停用用户；
- 可以使用全部风险查询和玩家详情功能；
- 可以新增玩家备注。

### 10.2 风控人员

- 看不到用户管理菜单；
- 不能直接访问用户管理功能；
- 可以使用风险查询和玩家详情；
- 可以新增玩家备注。

### 10.3 只读人员

- 看不到用户管理菜单；
- 可以使用风险查询和玩家详情；
- 看不到备注输入框和新增备注按钮；
- 直接调用新增备注接口时返回 HTTP 403；
- 不能修改系统中的任何业务数据。

### 10.4 停用用户

- 不能登录系统；
- 已经登录的用户被停用后，应退出当前登录状态；
- 再次访问系统时需要重新登录，并提示账号已停用。

## 11. 简单总结

第一版权限模型为：

```text
用户 → 分配固定角色 → 角色拥有固定权限
```

三个角色分别负责：

```text
管理员：管理用户并使用全部功能
风控人员：查询风险、查看玩家和新增备注
只读人员：只查看，不进行写操作
```

该方案规模较小、实现简单，能够满足第一期风险查询和玩家备注的基本管理要求，并为后续增加数据范围、自定义角色、导出审批和审计功能保留扩展空间。
