# 真人博彩风控后台第一期需求文档

## 1. 文档目的

本文档用于明确真人博彩风控后台第一期最小可用版本的业务范围、数据口径和验收标准。
第一期只实现三项风险结果查询和玩家备注。平台输出的是风险候选，不能仅凭规则命中直接认定作弊。

## 2. 建设目标

1. 查询高同桌率及庄闲对打的玩家关系。
2. 查询玩家与荷官之间的异常盈利和胜率关系。
3. 查询集中在牌靴后段下注的玩家。
4. 为玩家添加备注，并保存备注人员和备注时间。

## 3. 第一期范围

### 3.1 包含范围

- 同桌和庄闲对打查询。
- 玩家—荷官异常关联查询。
- 牌靴后段下注查询。
- 玩家详情页。
- 玩家备注的新增与查看。
- 三项风险数据每小时更新一次。


## 4. 数据范围与公共口径

### 4.1 数据源

```text
ods_a168_bet01：下注订单信息
ods_a168_bet02：结算订单信息
```

两张表通过 `bet01` 注单编号关联。关联前必须分别保留每个 `bet01` 的最新版本，不能直接连接原始ODS记录。

### 4.2 去重规则

同一 `bet01` 按以下顺序排序，只保留 `ROW_NUMBER() = 1`：

```text
updatetime DESC
sync_time DESC
dt DESC
```

### 4.3 游戏范围

第一期固定只处理百家乐：

```text
bet02 = 101
```

查询页面提供“游戏类型”下拉框，默认选中“百家乐”。第一期实际只返回 `bet02 = 101` 的数据；其他游戏选项暂作为页面预留，未纳入本期统计范围。

### 4.4 物理局

```text
下注表物理局键：bet03 + bet04 + bet31
结算表物理局键：bet03 + bet04 + bet39
```

同一玩家在同一物理局存在多笔订单时，先汇总成一条“玩家在该物理局的数据”，再计算局数和胜率，避免重复计算。

### 4.5 金额口径

```text
投注金额 = bet13 / bet11
游戏盈利 = (bet14 - bet13) / bet11
返水金额 = bet16 / bet11
净盈利 = bet17 / bet11
```

游戏盈利不包含返水；净盈利使用 `bet17 / bet11` 的正式结算结果。

## 5. 使用人员

第一期只面向风控人员。登录沿用现有系统账号，不单独开发用户和权限功能。备注人员ID和姓名从当前登录账号自动取得，不允许手工填写。

## 6. 页面与功能需求

第一期建设一个“风险查询”页面，通过三个页签切换风险类型；同时建设简版“玩家详情”页面。风险查询结果中的用户昵称可以点击并进入对应玩家详情。

三个页签的公共查询条件为：

- 游戏类型下拉框，默认百家乐。
- 开始时间、结束时间。
- 用户昵称。

说明：页面展示用户昵称，昵称格式为英文字母与数字组合；后端仍使用内部用户主键（如 `uid`、`bet05`）关联会员主数据，不改变数据表字段和统计逻辑。

页面首次打开时，开始时间和结束时间默认填充为昨天 `00:00:00` 至 `23:59:59`。不再将空时间自动转换为最近24小时；用户清空时间后按无时间条件查询。其他条件为空表示不限制。所有结果均提供分页，每页最多10条。

### 6.1 同桌和庄闲对打

额外查询条件：

- 最低共同局数。
- 最低同桌率。
- 最低对打率。

输入用户昵称时，同时查询该用户作为玩家A或玩家B的记录。百分比输入 `20` 表示20%。默认按照共同局数从高到低排列。

统计维度：

```text
玩家A + 玩家B + 统计窗口
```

玩家对统一保存为 `player_a < player_b`，不允许同时出现 `(A,B)` 和 `(B,A)`。

指标定义：

```text
共同局数 = 两名玩家共同参与的去重物理局数

同桌率 =
共同局数 / LEAST(玩家A总参与局数, 玩家B总参与局数)

对打局数 =
共同局中两名玩家分别下注Banker和Player的局数

对打率 =
对打局数 / 共同局数
```

输出字段：

- 玩家A、玩家B。
- A玩家局数、A玩家订单数。
- B玩家局数、B玩家订单数。
- 共同局数、同桌率。
- 对打局数、对打率。
- A玩家投注金额、B玩家投注金额。

排序要求：默认按共同局数降序排列；点击任意数值表头可按该字段排序，再次点击切换升序和降序。金额、比例、局数和订单数必须按数值排序，不能按展示字符串排序。

### 6.2 玩家—荷官异常关联

额外查询条件：

- 荷官ID。
- 最低非和局胜率。
- 最低关联订单数。

百分比输入 `65` 表示65%。默认按照关联订单数从高到低排列。

统计维度：

```text
玩家 + 荷官 + 统计窗口
```

同一玩家物理局出现两个及以上荷官时，该玩家物理局不参与统计。

胜率定义：

```text
局游戏盈利 > 0：胜局
局游戏盈利 < 0：负局
局游戏盈利 = 0：和局

非和局胜率 = 胜局数 / (胜局数 + 负局数)
```

输出字段：

- 用户昵称、荷官ID。
- 玩家统计窗口整体净盈利。
- 玩家在该荷官下的投注金额和净盈利。
- 非和局胜率。
- 关联去重订单数、关联物理局数。
- 首次关联时间、最后关联时间。

### 6.3 牌靴后段下注

额外查询条件：

- 最低总订单数。
- 最低后段订单比例。

第一期固定将 `bet04 >= 40` 定义为牌靴后段，页面不提供后段开始局号修改。百分比输入 `60` 表示60%。默认按照后段订单数从高到低排列。

指标定义：

```text
后段订单数 = 满足 bet04 >= 40 的去重订单数
总订单数 = 玩家统计窗口内全部去重订单数
后段订单比例 = 后段订单数 / 总订单数
```

输出字段：

- 用户昵称。
- 总订单数、后段订单数、后段订单比例。
- 后段投注金额、净盈利和非和局胜率。
- 首次后段下注时间、最后后段下注时间。

### 6.4 玩家备注

在任一查询结果中进入玩家详情页。玩家详情页展示玩家汇总数据、历史风险命中、三项风险关联明细和备注区域，并支持新增备注。

每条备注保存：

```text
note_id
player_id
note_content
created_by_user_id
created_by_user_name
created_time
```

备注要求：

- 同一玩家允许添加多条备注。
- 按备注时间倒序展示。
- 每条备注显示备注人员和时间。
- 备注内容不能为空，单条最多1000字。
- 第一期备注只允许新增和查看，不支持修改、删除及按备注条件查询。

### 6.5 玩家详情

从风险查询结果点击用户昵称进入玩家详情页，也可以在页面直接输入用户昵称查询。

查询条件：

- 用户昵称，必填且精确匹配。
- 开始时间、结束时间；页面默认填充昨天的完整时间范围，清空后按无时间条件查询。

页面按照以下区域展示：

1. 基本数据：用户昵称、去重订单数、参与局数、投注金额和净盈利。
2. 同桌和庄闲对打：关联玩家、共同局数、同桌率、对打局数和对打率。
3. 关联荷官：荷官ID、关联订单数、关联局数、非和局胜率、投注金额和净盈利。
4. 牌靴后段下注：总订单数、后段订单数、后段订单比例、后段胜率和净盈利。
5. 历史风险命中：命中时间、风险类型、关键指标和命中条件；
6. 玩家备注：历史备注列表和新增备注入口。

玩家详情页必须与风险查询页面使用相同的时间窗口和指标口径。各区域只展示汇总结果，不展示原始注单和趋势图。开发时复用三个风险页签的查询接口和备注接口，不重复开发另一套统计逻辑。

## 7. 后台菜单

```text
风险查询
├── 同桌和庄闲对打
├── 玩家—荷官异常关联
└── 牌靴后段下注

玩家查询
└── 玩家详情
```

## 8. 数据更新与页面要求

- 三项风险数据每小时计算一次，页面查询计算结果，不实时扫描全部ODS数据。
- 页面显示最近一次成功更新时间。
- 本次计算失败时继续使用上一次成功结果。
- 时间统一使用系统业务时区。
- 查询结果分页展示，每页最多10条。
- 表格支持点击表头排序，并在表头和结果摘要中显示当前排序字段及升降序方向。

## 9. 验收标准

### 9.1 数据验收

- 每个 `bet01` 最新版本只参与一次统计。
- 同一玩家同一物理局的多笔订单不会重复增加局数或胜局数。
- 玩家对只出现规范化后的一个方向。
- 同桌率、对打率、非和局胜率和后段订单比例可以根据分子、分母复算。
- 玩家—荷官歧义局被排除，和局不进入胜率分母。
- 金额和盈利口径符合本文档定义。

### 9.2 功能验收

- 三个风险页签均可按时间和用户昵称查询。
- 各页签的专用筛选条件生效，页面默认查询昨天完整时间范围，清空时间后不自动改写为最近24小时。
- 查询结果字段、排序和分页符合要求。
- 可以从风险查询结果进入玩家详情，也可以通过用户昵称直接查询玩家详情。
- 玩家详情正确展示基本数据、三项风险汇总和玩家备注，并与风险查询结果口径一致。
- 可以给玩家新增多条备注，并正确显示备注人员和备注时间。
- 三项数据每小时更新，页面能够显示最近成功更新时间。
